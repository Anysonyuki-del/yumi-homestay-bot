## 处理

| 项 | Spec §8 的处理 |
| --- | --- |
| H176-R1 独立出站重试打乱顺序 | 「可能危险」时，把固定避险正文与原有确认组合成一次客人回复，超长时复用分段接力；员工通知分别保留。判定与发送分开：从 `_apply_plan_risk` 抽出无副作用的 `_plan_hazard`，不再先调用带发送副作用的函数 |
| H176-R2 人工高风险分支 | 明确纳入 D-6：凡是软预规划后、不会再进入主回复就返回的分支，先判定危险。条件改为「只有仍会进入主回复的放行分支，才保留原消费点」。锁与事务合同沿用 `_plan_with_released_lock` |
| `process_recorded_message` 的人工早退 | 本版不改，只核对调用方；如需改，必须先复用 `_discard_stale_final` 的锁内检查 |
| P3 验收范围 | §8.3 按是否进入主回复分别断言：提前返回的行断言主回复 0 次；只有继续主回复的行才验成功与失败两个出口。门禁只同步软客诉提前返回，不重写主回复异常的处理 |
