- 对象：[实施交接](2026-10-18_claude-to-codex-1.70.5-tool-target-handoff.md)、[工具目标 Spec v1 及 §4](../specs/2026-10-18_tool-target-binding-spec.md)、当前未提交实现和相关测试、夹具、发布记录。

## 1. 结论

**先修 R175-1、R175-2、R175-3，再进入真实模型门禁。** 上轮 RV174-1/2 在标准拆项计划下已闭合，但新实现仍有三个 P2。其中粗粒度计划仍串日期，并新增丢弃正确结果；承接房号被扩成全店，以及周末合法调用被整组丢弃，均有改前/改后控制。

三个问题共用一条设计缺口：展示端的 `_ToolNeed` 从“计划项日期＋当前小句表面房号”重新构造需求，覆盖端却用 `ClauseTarget` 按原文小句、已解析房源与继承关系核对。两端并没有像 Spec §2.3 所说的那样使用同一目标。周末又在调用后独立扩展日期，扩大了这份差异。

建议一次统一需求生成和消费，不继续增加问法词表。D-1 真正没有日期时的兼容、D-2 无静态单元的延期、I174-4 已选 A 都可保留；本轮问题不要求扩大这些已确认范围。

## 2. 必须修复

### R175-1 · P2：把整项规划日期当成每个小句的日期，丢弃正确工具结果

**位置与原因**：`deepseek_client.py::_tool_targets`（2390–2400）给每个锚点小句直接传同一个 `stay=(item.check_in_date,item.check_out_date)`；`_tool_rooms_for`（2425–2429）要求完整区间相等。可是 `item_coverage.py::clause_target`（607 起）优先使用小句自己的明确日期，`turn_plan.py::_verify_dates` 只验证日期合法，不验证它与摘录一致。

**可复现输入**：

```text
10月8日401有房吗，10月10日302有房吗，501早餐几点，401呢
```

前两个小句放在同一个合法 `stay_query` 项，规划日期 10/8–10/9；静态部分另一个项。工具分别按 10/8–10/9、10/10–10/11 成功返回三房。当前结果在 10/8 下仍列 401 和 302，把 10/10 的正确结果全部丢掉，并说“10月10日302有房吗，这次没有查到对应的房态”。参考价同样丢掉 302 的 10/10 价格。正常与回退都成立。

更小控制：原文“10月8日401有房吗”，模型计划误填合法的 10/10–10/11，实际工具正确查询 10/8–10/9。当前仍丢弃正确结果；旧模块会展示 401 的 10/8 房态。此处原文明示日期，不属于 D-1 的“没有日期”。

**影响**：客户只改变句式、模型只改变拆项方式，就从可用结果变成“没查到”；旧跨日期串房也未根治。工具没失败，不能把这个少答描述为上游查询失败。

**建议**：冻结工具需求时直接使用与覆盖一致的小句目标。原文已证明的入住/退房端点优先；只有允许继承时才补计划日期。日期只给一个端点时，沿用现有覆盖合同，不凭空要求另一端必须等于某个粗项值；`unbound` 必须与“没有提供日期、按 D-1 兼容”分开。不要复制一套 `clause_target` 解析分支。

### R175-2 · P2：无显式房号的承接问句，被误当成全店需求

**位置与原因**：`_ToolNeed.mentions` 只保留 `room_mentions(clause.text)`；`_tool_rooms_for`（2433）将任一空 mentions 当成全店。但“当前小句没写房号”不等于“没有继承的房源目标”。覆盖端已经能从同项唯一房源继承。

**可复现输入**：

```text
明天401有房吗，能订吗，501早餐几点，302呢
```

第一项摘录“明天401有房吗，能订吗”，目标 401、日期 10/8–10/9；后半句形成静态单元。工具返回三房。当前输出“可订：401测试房、302测试房、501测试房”，`gap_units=[]`。将助手模块换回 HEAD，同一计划、工具和资料只展示 401。正常与回退均成立。

**影响**：客户追问同一间房能否订，系统把只问早餐的另外两间也加入房态。它是 RV174-2 全店修复带来的范围扩大，不能通过让模型少拆小句解决。

**建议**：需求保存已经解析/继承后的目标状态，不用空 mentions 代表全店。显式全店、继承单房、未知房号、歧义候选和未绑定目标应保留区别。真正全店＋点名仍保留全店；同项单房承接继续单房。对“401，明天还有房吗”的枚举交接也应复用 `_clause_rooms` 的结果，该类似遗漏在旧版亦存在，不把它冒称为本版新增。

### R175-3 · P2：周末两种合法住法选得不同，就把已经查到的两组结果全部丢掉

**位置与原因**：`_respond_with_plan`（4753–4757）给 `_weekend_reply_parts` 的目标来自模型原始 `arguments`，而 `_weekend_argument_options` 已把实际执行展开为两种住法。I175-1 避免了“逐个 option 对照单一计划日期”的漏答，但仍要求两个模型阶段选中同一种住法。

**可复现输入**（固定今天为 2026-10-07）：

```text
这周末401有房吗，501早餐几点，302呢
```

计划将周末绑定 10/9–10/11；主调用选 10/10–10/12。系统实际成功查询 10/9–10/11 与 10/10–10/12 两组，但原始参数不匹配需求，最终只答早餐，房态记 `tool_uncovered`。仅把主调用改为 10/9–10/11，当前又能展示两种住法。旧模块两种调用起点都能展示两组；正常和回退均作成对控制。

**影响**：再次依赖规划与主模型两次选择偶然一致，同一问法会出现“查到了却说没查到”。这正是周末两方案既有功能原本要消除的不稳定。

**建议**：把“该原文需求允许的周末两种日期”在需求侧冻结，再让每个 option 按自己的日期消费这些需求。复用 `weekend_stay_options`，扩展必须绑定所属工具需求，而非把整轮所有房间随某次调用复制到两个日期。保留当前明确日期不触发裸周末扩展的边界。不能简单恢复逐 option 严格比较单一计划区间，也不能取消日期筛选。

## 3. 两处实施补充与门禁调整

- **I175-1 尚不能接受为闭合**：理由识别了一个真实问题，但 R175-3 证明替代方案仍有新回归。Spec §4 应改成需求侧定义合法方案，确认后再实施；仅追加“原始参数共用”不足以代替原合同。
- **I175-2 方向可接受**：成功工具结果因目标不匹配被全部丢弃时，构造确定性回执，保留静态答案并报告工具缺口。`test_call_on_an_unasked_date_is_not_shown` 两出口独立运行通过。源码中 `tool_parts` 在循环外累计，新回执仍消费累计结果，因此“后一次空匹配覆盖掉前一次已接受结果”的推测不成立。未授权工具仍在执行前被拒，本补充不等于完成 I174-4 的纯静态通用回退。
- **早餐诊断恢复合理**：新增独立编号和 9907/9908，卫浴承接场景保留，SR-遗失未移出 must_pass。`reply_regression.py::gate_verdict`（201 起）会把三次全过的 known failure 自动写入“建议基线”的 must_pass；若早餐优先级仍未决定，不能只因偶然通过就直接采纳该晋升。建议发布时明确审阅该条基线，或单独保留诊断身份；不必为此修改冲突放行规则。
- **新增用例数量需更正**：实际是 13 项，10 个缺陷回归＋3 个保持现状对照（D-1 两项、目录一项）。collect-only 为 `13/286`，对应相关总数从 424 到 437、全量从 3281 到 3294。交接、发布记录和 todo 的“14 项/另外 4 项”不准确。它不构成第四个代码阻断项。

## 4. 一次完成的补修合同与验收

先修订 Spec §2.1–§2.3：需求不是“当前小句房号词面＋整项日期”的组合，而是与 `_tool_coverage` 相同的已解析目标，外加已证明的合法日期方案。`ClauseTarget` 已有房源和日期端点、未绑定状态，布局也已有 `RoomResolution`、枚举交接及 B 父日期；优先从它们产出共享需求，不新增解析器、通用调度框架或词表。保留 unknown/ambiguous/unavailable 的现有说明能力。

建议同一补修中覆盖以下组合，避免下一轮又逐层补洞：

| 维度 | 最小成对验收 |
| --- | --- |
| 计划形状 | 标准拆项、两日期同项、合法但与原文明示日期不一致的计划；房态与参考价 |
| 范围 | 单房后无房号承接；纯房号枚举交接；真正全店＋单房；不同日期的全店不能放开另一天 |
| 日期 | 小句仅入住日、完整区间、未绑定与真正无日期分开；B 父日期与调用相同/不同 |
| 周末 | 计划选周五/周六 × 主调用选周五/周六；两个 option 都按需求筛选；明确日期不误扩展 |
| 状态 | unknown、ambiguous、unavailable；成功空结果；一个工具失败、另一个成功；保留正确静态事实 |
| 出口 | 正常、工具后非法协议回退；两次成功结果累计；后一次结果被全部筛掉不能丢前一次结果 |

把“调用参数符合计划日期”改为“结果确实属于已证明的客人需求”。共享目标同时服务展示和缺口核对；不以覆盖层追加一句未确认来容忍展示端已放入的错范围结果。D-1 只用于真正缺日期的需求，不能覆盖原文已明确日期；D-2、I174-4 不顺带扩范围。
