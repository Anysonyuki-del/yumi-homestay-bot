## 3. 代码审查（rc4 → v1.70.0）

### 3.1 认可的部分

- `DeepSeekGuestAssistant._fact_layout` 前移到知识检索之前，`_item_dates` 只算一次并存进 `_ItemLayout.item_dates`。`_merge_item_knowledge`、`_item_evidence_plan`、`_shared_grounded` 以及正常、联网早返回、`availability_fallback` 三个出口都读同一个布局，删掉了原来四处各自重算日期的写法。行为等价，房源改用 `entry.property_id`，与原 `_item_property` 口径相同（映射不到的房号为空）。
- `relative_calendar_day` 只解析与今日相关的单日：今天、明天、后天、本周/这周某日（周一为起点）。多个不同单日、序数日、范围一律拒绝。`today` 在本轮开始时冻结，跨午夜不变。
- `_item_dates` 只在独立 `static_fact` 项、没有模型日期时才用客人给的日历单日作为该项目标，不会把粗住宿项范围外的「明天」借过去。
- `_RELATIVE_DATE` 扩充的序数日、次日、英文 next day 等只会让小句被判为未绑定，不会造成错答。

### 3.2 RV-1（P2）：「周末」静态问题一律回未确认

**复现。** 合成资料只有一条无日期限制的「早餐几点开始？/早餐7:30开始」，计划为单项 `static_fact`，模型选中该条目：

```text
早餐几点开始       → 早餐7:30开始。
周末早餐几点开始   → 当前审核资料尚未确认早餐信息。……
```

`static_clause_dates("周末早餐几点开始", …)` 返回 `None`。原因：`_RELATIVE_DATE` 认出「周末」所以 `relative=True`，但 `relative_calendar_day` 不解析范围、返回空，于是走「无法确定的相对日期不借父区间」分支，记 `scope_unbound`。rc4 及以前这一问会按当天资料作答。

**影响。**
- 「周末有早餐吗」「周末停车收费吗」「周末前台几点下班」这类很常见的一般政策问题，现在不论资料是否限期，都确定性地回未确认，而且不转交管家（范围未绑定不可转交），缺口不会被补上。
- 门禁 154 个场景里没有含「周末」的，rc5–rc7 都覆盖不到。上线后只能从真实对话里发现。
- Spec §5/§6 写了「周末等未解析范围记未绑定」，但没有评估它对「无日期限制的一般政策」的影响；发布记录的风险段也只提了粗住宿范围外和序数日。

**建议（需走 Spec 确认）。**
1. 推荐：把「周末」「这周末」按日历解析成本周六到周日两天的范围，与「本周X」同属日历合同，不依赖入住锚点。之后复用现有按有效期分段的逻辑：两天资料相同就直接作答，不同就分段，查不到才回未确认。
2. 备选：所有合法候选都没有有效期时，日期不影响答案，未绑定的相对日期可以退回原日期作答；有限期候选时仍保守未绑定。规则更窄，但要多一个判断。
3. 至少：把 RV-1 写进发布记录风险段，并补一个含「周末」的门禁场景，确认取舍是有意的。

验收建议：「周末早餐几点」在无限期资料下作答；周六、周日资料不同时分段；只有工作日例外资料时不混入；粗住宿范围外的周末仍未绑定；正常与回退出口一致。
