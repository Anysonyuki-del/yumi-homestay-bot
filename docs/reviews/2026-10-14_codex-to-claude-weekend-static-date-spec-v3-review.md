## 2. V3-R1（P2）：单日展示需保留年份与语言边界

Spec §2.4推荐统一“10月11日（周日）：”，但修改点是共享[build_evidence_plan](/Volumes/02/code/homestay-bot/src/homestay_bot/services/knowledge_evidence_policy.py:636)。它没有语言参数，调用方也包含英文及非周末跨期问题。V3-E1实际输出完整的跨年日期；按推荐写法将丢掉年份，并给英文答案加中文前缀。

**最小修订：**D-W6优先选择单日 `YYYY-MM-DD：`，多日保持现有ISO范围；年份完整、语言中性，不增加语言参数。若仍选择自然日期，须明确中文保留年份和英文显示契约，并把涉及的调用方纳入范围，不能从问题文字猜语言。

内部日期仍使用冻结的本地date和段边界。日期前缀识别与展示不能改变主题、凭据专门拒绝、gap_unit或原文单元；不在等待模型后重读系统时钟。grounded和missing采用相同显示规则。

**验收：**中文与英文各覆盖单日分段、跨年、多日范围、正常答案加缺失日；最终正文保留完整日期。门锁凭据仍为out_of_scope专门拒绝，不因日期前缀变成可转交缺口。无需为展示调整重跑无关浏览器测试。

## 3. V3-R2（P2）：门禁要核对日期与对应答案，来源另证

Spec §2.5要求“日期、时刻及来源对应正确”，目前只有目标，没有与真实判定能力绑定。[judge](/Volumes/02/code/homestay-bot/src/homestay_bot/tools/reply_regression.py:94)逐片段匹配must_include，不建立对应关系，也不读取source_ids。

V3-E2：要求9月26日、8:30、9月27日、9:00全部出现时，“周六9:00、周日8:30”仍通过；提交不相关source_ids也不改变结论。仅把新编号变为must_pass并不能修复这一误判。

**最小修订：**在K-周末分日的must_include中匹配完整“日期前缀＋对应审核答案”，格式跟随最终D-W6。例如选择ISO单日时要求 `2026-09-26：早餐8:30开始` 与 `2026-09-27：早餐9:00开始`，保留既有空白归一能力，不把两者拆成独立时间和日期。

同时在该场景单独添加平时7:30的负向约束，防止正确答案后夹带错日资料；不能把7:30加入全局禁词而破坏既有无期限早餐场景。若允许多种合法格式，在每个完整日期答案组合中提供有证据的替代形式，仍要拦住互换。

来源验收放在离线完整回复链路：逐个ReplyPart核对ReplyEvidence的source_id、target_date/target_end_date以及正文中的时刻，不能只检查两个来源编号“曾经出现”。真实模型门禁验证最终日期答案，离线来源断言验证证据归属，二者分别报告。无需让judge支持新的来源字段。

**验收：**正确答案通过；时刻互换、错误日期、正确答案夹带平时答案和空结果失败；错来源在离线断言失败。新增项仍按Spec独立三次全过再晋升，最终all保护旧稳定集合，缺结果仍阻断。当前is_stable_pass对不足三次或夹一次失败均返回False，可以复用。

## 4. V3-R3（P3）：边界点不等于分段数

Spec及交接中的“三段及以上加日期”不准确。[实际条件](/Volumes/02/code/homestay-bot/src/homestay_bot/services/knowledge_evidence_policy.py:691)是len(ordered)>2，ordered为边界点；三个边界点对应两个分段。V3-E1/E3均只有两个分段，已有日期前缀。

**修订：**更正为“两个及以上分段”，Spec和交接的事实说明保持一致。展示方案是否采用D-W6是另一个待确认决定，不要把事实更正当作批准展示变更。

## 5. 9999预检与302回退的处理

V3-E3说明现有静态知识路径可以映射仅在知识中存在的9999，并不必然要求Hostex存在该房源。因此优先保留独立测试房号，避免无依据修改公共房态夹具。

预检的四个条件适合作为冒烟检查，但不够定位失败原因。两个候选未进入可能来自日期绑定、知识预算、scope过滤或测试装配；工具调用可能来自合成响应或真实规划模型的决定，不能一律称为虚构房号不稳定。

建议把自动回退改为：冻结失败输入并定位到具体分支，只有证明确属本场景虚构房源装配问题才改302。换后重新做新场景的完整正向预检，并检查相关旧场景候选与最终行为；不是只证明旧候选未变就调用真实门禁。代码缺陷继续按已确认Spec修复，若需要扩大范围则先更新Spec。

这是预检决策的完善建议，不是已复现9999失败或302污染；本轮未验证真实规划模型及全部302旧场景。
