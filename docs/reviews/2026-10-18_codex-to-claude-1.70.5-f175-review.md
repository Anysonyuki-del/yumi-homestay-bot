# Codex → Claude：1.70.5 F175-1 修复复审

日期：2026-10-18。对象：`2026-10-18_claude-to-codex-1.70.5-f175-handoff.md`、工具目标 Spec §8、当前源码与新增回归。业务文件只读。

## 1. 结论

**F175-1 标准反例闭合，仍有一项同族 P2：F175-2。** 新增的父句绑定正确，但上游旧枚举交接能先抢走追问，使新绑定完全不执行。建议先统一“向前承接”和“向后枚举”的归属优先级，再跑真实模型门禁。

这不等于必须重写解析器。当前已有静态追问优先于枚举的入口，应把合法工具追问纳入同一条归属规则；继续只改最终展示或覆盖检查，会漏掉更早被交接的片段。

## 2. 已闭合部分

当前 `src/homestay_bot/integrations/deepseek_client.py`：

- `_follow_up_anchor` 只接受有限省略句式，并在另一个问题或非追问片段前停止；`_layout_tool_checks` 同时继承父检查的 flags、日期和 options，不再把整项工具类型并集用于这条已绑定追问。
- `test_follow_up_needs_only_its_parents_fact` 八种组合独立通过：同项与拆项、两类事实顺序、正常与协议回退；原 F175-1 假缺口消失。
- `test_follow_up_not_shown_in_a_non_parent_fact_query` 通过，额外调用非父工具时不会因虚假需求展示 302。
- `test_mixed_facts_with_weekend_follow_up` 通过：无自身日期的小句可从裸周末项继承两方案，追问使用其父事实类型。该扩展方向与共享日期合同一致，本轮未发现它导致的新可复现错误。
- `test_non_follow_up_fragment_keeps_item_rule` 通过：非省略订房片段没有被一并改成向前追问。

## 3. F175-2 · P2：后续工具问题仍会抢走已具有父句的追问

### 输入与成对证据

```text
10月8日401有房吗，302呢，10月10日501多少钱，401早餐几点，501呢
```

工具按参数正确返回 10/8–10/9 房态、10/10–10/11 参考价。最后的早餐追问使本轮存在静态单元，因此确实进入本版的按需求筛选，不属于 D-2 延期的“无单元轮次”。

| 合法规划形状 | 当前结果 |
| --- | --- |
| 前三个小句拆项，302呢 为独立 static_fact | 10/8 列 401、302 房态；10/10 只列 501 参考价。符合原文承接。 |
| 前三个小句同一 stay_query 项 | 10/8 只列 401 房态；10/10 列 302、501 参考价。302 被移到后一句。 |

两种形状的 `gap_units` 都为空。反向改成先问 401 参考价、后问 501 房态时，同项版本也把 302 移到 10/10 房态，漏掉 10/8 参考价。正常和协议回退均复现，共八次对照。

**影响**：客人追问的事实类型和日期同时被改掉，并静默漏答。回答里的数字有工具来源，却不是这句追问所要求的事实；规划稍微合并小句就改变产品语义，仍未达到泛用化目标。

本轮未做完整旧版工作区重放，因此将它称为当前范围残留，不断言枚举机制是本次新引入。它是 F175-1 父句绑定未覆盖的实际路径。

### 真实调用链与依据

均在 `deepseek_client.py`：

1. `_fact_layout` 先调用 `_static_led_follow_ups`（约1619行），再 `_clause_rooms`（约1630行），最后才 `_bind_units`。
2. `_static_led_follow_ups` 只保护“静态问题后面的省略追问”（约2756行）。前句是工具问题时，302 不在保护集。
3. `_clause_rooms` 把没有工具锚点和残留的“302呢”加入 pending，遇到后面的“10月10日501多少钱”就合并房源，并设置 `delegated=True`（约2854–2887行）。片段没自身日期即允许并入，未先检查它已有合法的前向父句。
4. `_bind_units` 对 `entry.delegated[index]` 跳过省略绑定；交接后的片段也没有 orphan target。新 `_follow_up_anchor` 只在 `orphan == "target"` 时调用（约2084行），因此根本看不到被抢走的302。
5. 后句检查已经持有302与501的合并房源，展示与覆盖都一致地认为302问的是后句，故不会报缺口。

### 最小修复建议

在枚举交接前，按冻结的全文小句和计划归属确定合法的省略承接，至少把“紧随工具父句、同一行、仅隔连续追问”的片段保留给其父句；枚举扫描不得再消费这些区间。优先扩展现有前置保护入口或复用 `_bind_units` 的父句关系，避免第三套近似判定。

边界必须同时保留：

- 真正的前置枚举 `明天302，401还有房吗` 仍可向后合并；不要把所有无锚点房号都禁止枚举。
- “302呢”已有合法前向父句时，后续任何工具类型和日期都不能改变它归属；同项、拆项、连续追问一致。
- 静态问题、动作、漏项与换行仍阻断承接；重叠项只归一个所有者。未知房号仍按既有身份合同处理。
- 不在最终正文删除错误结果来遮掩：必须先修归属，使展示需求和覆盖检查共享正确父句。

### 一次补齐的验收

1. 本报告脚本的八组改为正确行为断言：同项/拆项均只在前句对应的事实和日期显示302。
2. 同日不同工具、同类工具不同日期、周末父句后接另一工具、连续 `302呢，501呢`；每组检查房源×事实类型×日期，不仅断言“没有缺口”。
3. 保留已有纯枚举、静态追问阻断、跨行拒绝、非省略订房片段、父日期优先和周末缺行回归。
4. 加“本轮有静态单元”的断言或布局证据，避免测试意外落入 D-2 后用整轮结果掩盖错绑。

## 4. 交接中“跨行已知上限”的核实

交接和 Spec §8 声称同一项跨行仍会承接，但当前以下控制已经拒绝：

```text
10月8日401有房吗
302呢，501早餐几点
```

将前两行放同一 stay_query 项，当前仅展示401房态，302记 `scope_unbound`。原因是 `_bind_units` 已按全文换行先冻结 D 单元，后续 `_layout_tool_checks` 跳过该单元；局部 helper 看不到换行并不能证明全链路没有换行防护。

建议收窄或更正该上限表述，并保留一个真实助手回归。此控制只证明上述输入，不能据此宣称所有跨行及前后枚举组合都已覆盖；本项不额外列为业务阻断。
