## 2. 新问题：来自 1.70.7 复审（待决）

### RV177-1 / P3：普通推荐指令会追加到店内设施问题（已核实）

- **现象**：1.70.7 给 `tourism.py::_STABLE_TOURISM_PATTERN` 新增了别名 `有(?:啥|什么)(?:好)?玩`。它会命中「玩具」「玩意」「玩法」，「房间有什么玩的」「电视有什么玩的频道」也会命中。
- **后果**：`deepseek_client.py::_respond_with_plan` 因此给这些本店事实问题追加 `_STABLE_RECOMMENDATION_RULE`，即「先推荐店外去处、不因缺资料拒绝」。
- **已核实**：
  - 新旧分类对照、合成替身证实指令被追加（Claude 与 Codex 各自复核）；
  - Claude 最初建议的正则没有闭合，已撤回。
- **当前方案**（Claude 回复 §6.1，已取代 §2 的「区间相交」）：
  - 不改分类器，只改唯一的 stable 消费点：本轮有可用计划，且某个有效的 `external_info` 事项**自己的原文**切句后至少有一个小句分类为 stable，才追加；
  - 计划不可用时不追加。
  - 「区间相交」被 Codex 用「……还有……」的反例证伪，见回复 §6.1。
  - 依据：stable 在 src 中只有这一个消费者；rc3 门禁中三个用到该指令的场景，规划都是 `external_info`。
- **残余风险**：规划把真正的推荐误标成本店事实时，会收回这条指令，可能重现「只追问、不推荐」。需要真实门禁 all 衡量。
- **未做**：没有用真实模型验证回复是否实际变差。
