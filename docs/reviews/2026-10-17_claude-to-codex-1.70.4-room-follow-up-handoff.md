## 1. 实现要点

改动清单见发布记录。数据流如下：

1. `_fact_layout` 照旧算出各项的小句、所需事实、房号和日期，最后交给 `_bind_units` 一次冻结单元。冻结之后，正常出口和工具后协议回退都读同一份单元。
2. `_bind_units` 先把所有计划项的小句按原文区间排序，确定唯一归属：起点更早优先，其次覆盖更短，再其次编号更小。非本店事实项也占位。然后按原文顺序扫描，用 `previous` 记住同一行紧挨着的前一个单元。
   - 结构不匹配：沿用现有流程（A 类）。
   - 结构匹配、前一个是工具问法、本项不是 static_fact：归 B，不建单元，沿用 1.70.3 的覆盖逻辑。
   - 结构匹配、前一个是静态问题、房号 resolved、父日期已绑定：归 C。
   - 其余：归 D。
   - 同项点名多个房间时，静态小句按自己的房间建 own 单元（D-T2）。
3. 检索：单元用自己的房源、日期、规范问法和父句条件原文检索（`trigger_text`），排除词仍按本轮全文判断。
4. 取证：`_item_evidence_plan` 按原文顺序走每个小句，遇到单元就交给 `_unit_evidence`。
5. 工具：`_tool_targets` 按 §2.7 的三种状态给出筛选目标；`tool_free` 的项不开放工具。

## 2. 实施中对 Spec 的补充与偏差（请重点审查）

| 编号 | 内容 | 原因 |
| --- | --- | --- |
| I174-1 | 新增单元类别 elsewhere：摘录重叠时，不拥有该区间的计划项对这个小句不取证、不出缺口、不开放转交 | 回归发现：整句项已经答了 302，重叠的「302呢」项又按普通静态问题报了 302 的 knowledge_missing。Spec §2.4 只规定归属，没写非归属项怎么处理。目前只在归属项真的冻结了单元时才标 elsewhere，其他重叠沿用旧行为 |
| I174-2 | 每个小句都已成为单元的计划项不做项级检索，也不占 `_PLAN_RETRIEVAL_ITEMS` 名额 | 「10月8日401早餐几点，302呢；10月10日401早餐几点，501呢」分两项时，两项各占一个名额，加上四个单元，超出上限 4，501 被记为 budget。这类项的项级候选从来不被使用 |
| I174-3 | 规范问法同时去掉父句的日期写法（`strip_room_mentions`） | 否则卡片上会出现「2026-10-08：302明天早餐几点」。日期已冻结在单元里，并写进分段标签 |
| I174-4 | 只有静态单元时，不存在「工具后协议回退」出口 | Spec §2.6 要求 P5、P6 在主模型硬调用工具后，正常和工具后回退两个出口都只有静态答案。实际上本版对这类项关闭了工具，硬调用会被当成未授权工具拒绝，随后输出不合法就整轮不可用。这是既有协议行为：不带追问的纯静态问题同样如此，对照用例 `test_unopened_tool_then_invalid_output_is_existing_unavailable_path` 证明。因此回退出口只在有真实工具需求的用例里覆盖 |
| I174-5 | 动作请求被误标成 static_fact 时，本地无法识别 | 真实规划会把「帮我开张发票」标为 service_request，它作为非本店事实项占位，能正确阻断承接（测试按此构造）。如果规划把它误标为 static_fact，「302呢」会承接成「302帮我开张发票」并按资料问题取证。概率低，列为已知上限 |
| I174-6 | static_fact 项里的「302呢」接在工具问法后面时归 D，不归 B | B 只在追问所在项是住宿或目录项时成立。静态项里不开放工具，按 1.70.3 的做法保留 scope_unbound |

## 3. 回归覆盖（`tests/unit/test_room_identity.py`，新增约 64 项）

- 结构匹配：19 种写法，包括 C4-1 的写法、相对日期、序数日、非法日期、订房说法。
- P1 至 P5，以及目录误标：两间各答自己的早餐，按原文顺序，无缺口，不问入住。
- P6（带日期的住宿误标）：无工具调用、房态硬调用、房价硬调用三种情况。
- 未开放工具后输出不合法：不可用对照（I174-4）。
- 连续追问；模型把 401 的条目选给整项时与单元候选取交集；重叠项调换数组顺序；两组不同日期；不能借父句日期确认追问。
- D 类：999、单独的「302呢」、隔换行、同号异栋 1803、父句是服务请求。每种覆盖 static_fact、stay_query、catalog_query 三种规划；模型主动选中缺口编号，也不生成转交候选。另有房源资料读取失败。
- A 类对照：「我想订302」「我想住302」「我要302」接在早餐问题后，不被吞成早餐问题。
- 继承成功、真缺资料：缺口文本为「2026-10-08：302早餐几点」，转交候选与之一致。
- 超预算记 budget，不可转交。
- 工具三态：全店房态不被追问房号收窄；点名目标只展示被点名的房间，追问提到的房间行不展示。正常和工具后回退两个出口都覆盖。

**Spec §2.6 中尚未覆盖的项**（请判断是否需要在发布前补上）：

- 父句带附加条件词、另一个独立问题带条件、全文有排除词时，单元检索的 `trigger_text` 与 `exclude_text`；
- 父句冲突、需要复核、期间否决时，追问仍独立取证；
- 「有什么房型」之后接静态追问；
- 有真实工具需求但结果为空；
- 房态父句后的带日期片段：由 1.70.3 已有用例覆盖，本版没有新增。
