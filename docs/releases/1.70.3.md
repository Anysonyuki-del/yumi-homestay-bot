## 改动清单

本版只改 `src/homestay_bot/integrations/deepseek_client.py`：

| 符号 | 改前（v1.70.2） | 改后 |
| --- | --- | --- |
| `_asks_static` | 未接管的房号片段会被送去静态取证，有时开放可转交的资料缺口 | 住宿、目录项里没有剩余内容的小句一律不走静态取证，不开放资料缺口，也不补静态未确认；不再按订房动词区分 |
| `_clause_rooms`，`_ItemLayout.orphans` | 只处理「片段 + 紧随其后的工具问法」，句尾追问、日期中断时片段被丢弃 | 扫描结束后统一标记所有未交接的房号片段：`"target"` 表示日期可证明（没写日期；或只写入住日且与规划一致；或完整区间两端都与规划一致），`"unbound"` 表示证明不了 |
| `_tool_coverage` | 只核对有工具锚点的小句；目录有任一行就算覆盖 | 房号片段也按实际证据核对，`"target"` 用片段房源和规划日期作为目标；目录点名房间时逐个房源核对；缺口为 tool_uncovered 或 scope_unbound，都不可转交 |
| `_uncovered_text` | 目录缺口用泛化说明 | 点名房号时引用片段原文：「「302呢」这次没有查到对应的房源资料」 |

## 风险、未覆盖与回滚

- 房号片段直接沿用规划的住宿日期：规划日期本身错了，片段也会跟着错；不过同一项里带工具锚点的小句用的也是同一份规划日期。
- 住宿项里一个工具锚点都没有时，房号片段默认核对房态；不会因此生成价格证据。
- 目录里对不上的房号只说「没有查到对应的房源资料」，不说「没有找到这个房间」。
- 只写退房日的片段一律记为未绑定；复杂或不支持的日期写法按现有解析器保守处理。
- 回滚：回退到 v1.70.2 即可，没有迁移和数据需要恢复。
