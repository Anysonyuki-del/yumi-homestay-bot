## 改动及依据

| 编号 | 文件与符号 | 改动 |
| --- | --- | --- |
| B24-R1 | `conversation_service.ConversationService._apply_plan_risk`（新增）、`_process_model_reply_body` | 计划里的当前危险与可能危险由成功与主回复失败两个出口共用处置；失败出口先过时复核、再处置，处置后结束本轮 |
| B24-R2 | `answer_policy.resolve_handoff_reason`；`ConversationService._classify_complaint`（新增），`handle_message`、`process_debounced_message` 使用 | 全部文本变体都看完，硬理由按优先级先于情绪词复核；客诉分类优先取非情绪词结果，保留风险等级 |
| B24-R3 | `deepseek_client._merge_item_knowledge`（返回各项合法候选）、`_selection_evidence_plan`、`_validate_decision(item_knowledge=)` | 每项只用自己的合法候选核验、判冲突与回退；点名房号映射不到时不含任何房间专属条目 |
| B24-R4 | `AssistantDecision.item_answers`、`ItemAnswer`、Schema、`_ITEM_ANSWERS_RULE`、`_with_item_answers`、`_action_only_plan`、`_PROPERTY_FACT_KINDS`；`ConversationService._process_model_reply_body`；门禁运行器 | 静态证据只接管本店事实项，其余项（店外、寒暄、不明确等）接上主调用逐项回答并照常过滤；计划全是动作项时证据计划不接管整轮；只有询问事实的项算本店专属；模型正文全被出口过滤时客人只收到实际登记结果 |
| B24-R5 | `turn_plan._verify_risk` | 先判字符串类型再查白名单，非法类型一律规划失败 |
| B24-R6 | `knowledge_evidence_policy._same_question`（新增）、`verify_selected_evidence` | 冲突分组纳入标准问题实质相同（归一化相同或相邻两字重合度 ≥ 0.6）的合法候选，不看 related 标签；保留只查所问钟点或收费、按问法分组 |

**实施偏差**（相对修复 Spec）：§2.4 写的是「计划里没有 static_fact 项时不让证据计划接管」。候选门禁 rc-1.69.1-1 实测这条收得太宽：规划把「有无障碍房间吗」判成房型推荐、把停车追问「How much is it?」判成房价时，能作答的现行证据计划也被关掉（K-无障碍-D、MT-停车EN 退步）。已改为只在计划**全是动作项**时生效，并补回归用例。
