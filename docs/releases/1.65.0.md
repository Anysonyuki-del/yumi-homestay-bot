## 风险与未覆盖

- 真实上游迟到建单和错误码契约没有验收；不能把任一错误码当作已经证实未建单。所有迟到丢弃都提醒管理员。
- 本地浏览器用真实路由响应加项目样式检查静态提醒，不是生产浏览器导航或完整 JS 联调。生产是否有可用于提醒验收的审批 / 迟到审计，部署后只读核对；不创建合成生产数据。
- SQLite 文件数据库的完整并发压力未测；部分历史测试直接建引擎，不会获得项目工厂的监听，全量通过不等于每个 SQLite 引擎都采用了修复。
- 审计失败会回滚、抛错，诊断日志只能保底，管理员此时没有新审计提醒；不引入自动重试或外部通知。
- 详情页最多显示 10 条审计，审计目标暂无新索引；没有「已核对」按钮，沿用 365 天保留阈值，实际由既有清理流程执行。
- 本地全量的 10 条警告包括 Starlette / Alembic 弃用提示、FAQ / 知识导入测试阶段的 SQLite 连接回收与线程关闭警告；未修复，也未断言全部为历史警告。
- 前序 Spec 中的生产审批数量是历史信息，本轮不沿用它证明当前生产状态。健康 degraded 的原因与是否变化，以本轮运行诊断为准。

无数据库迁移；需要回滚代码时，恢复部署前 c5aac99f8a0943e72513b3a6df1d3e8bd910b332 / v1.64.0 并只替换 API，保持 PostgreSQL。保留经复验的数据库、配置、上传和源码备份。仅代码问题不恢复数据库，避免覆盖发布后正常业务数据；数据库恢复必须另行确认数据时间边界。
