## 改动清单

### `services/item_coverage.py`

| 符号 | 说明 |
| --- | --- |
| `_FOLLOW_UP`、`is_room_follow_up` | 第一步结构匹配（§2.1）：小句里有任何日期写法（含无法绑定的）就不匹配；然后只去掉空白和外层标点，完整匹配「302呢／那（么）302呢／302的呢／302也是吗／302也一样吗／302也这样吗」 |
| `strip_room_mentions` | 去掉问法里的房号写法、日期写法（绝对日期、相对日期、周末限定）和外层标点，作为继承来的话题。日期另外冻结在单元里，并写进分段日期标签 |

### `integrations/deepseek_client.py`

| 符号 | 说明 |
| --- | --- |
| `_StaticUnit`（新增） | 冻结的静态单元，记录类别、规范问法、房源、日期、条件原文和展示文本。类别：C 表示承接；own 表示同项多房间时按自己房间作答（D-T2）；D 表示结构匹配但绑定失败；elsewhere 表示摘录重叠时归另一个计划项 |
| `_ItemLayout.units`、`tool_free` | 单元表；住宿或目录项的每个小句都是单元或纯静态小句时，`tool_free` 为真 |
| `_bind_units`（新增） | 第二步绑定（§2.0、§2.2）。按原文区间确定唯一归属：起点更早优先，其次覆盖更短，再其次编号更小。非本店事实项占位并阻断承接。同一行、相邻、只往前看一个单元：前一个是工具问法归 B；是静态问题、房号确定、日期已绑定归 C；其余归 D |
| `_merge_item_knowledge` | 单元用自己的房源、日期、规范问法和父句条件原文检索，计入 `_PLAN_RETRIEVAL_ITEMS`。每个小句都已成为单元的计划项不再做项级检索，也不占名额；超出名额的单元记 budget |
| `_unit_evidence`（新增）、`_item_evidence_plan` | 按原文顺序逐个单元取证。模型的证据选择先与单元的合法候选取交集，交集为空时走本地证据计划。D 记 scope_unbound，elsewhere 不出分项 |
| `_gap_unit_offers` | C 和 own 单元开放缺口编号，文本为带日期的规范问法；D 和 elsewhere 不开放 |
| `_plan_tool_names` | `tool_free` 的项不开放工具 |
| `_tool_targets`（新增）、`_tool_reply_parts`、`_weekend_reply_parts` | 工具目标有三种状态（§2.7）：没有工具需求时为 None，工具分项丢弃；需要工具的小句都没点名房间时，按全店或上下文目标；点名了房间时只按这些房间筛选。只有本轮存在 C 或 D 单元时才重新计算，否则沿用原来的本轮房号 |
