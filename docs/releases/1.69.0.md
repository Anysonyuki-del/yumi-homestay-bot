## 改动及依据

### 第二批：轮次计划契约 + 知识与只读查询（Spec §2.3、§2.4）

- `src/homestay_bot/services/turn_plan.py`（新增）：`PlanItem`、`TurnPlan`、`PlanOutcome`、`verify_turn_plan`、`usable_plan`、`planner_messages`。
  - 类型白名单 13 种；`id` 唯一；`withdraws` 只允许撤回项使用。
  - 摘录必须出现在冻结正文；给定位置精确命中即有效，不命中但摘录唯一出现时按唯一位置改正（偏差 X2）。
  - 房号必须是原文里的数字；日期走 `validate_stay_date_range`；风险标签白名单，不认识的值让整份计划失败。
  - 格式错误、Schema 不符、全部摘录失效 → 规划失败。
- `src/homestay_bot/integrations/deepseek_client.py`：
  - `DeepSeekGuestAssistant.plan_turn`：一次无工具短调用，6 秒超时（D5），任何失败返回 failed，不抛异常。
  - `respond`：内部探针之后、检索之前规划；合并阶段带来的计划按 `source_sha256` 复用；返回的决定总带本地计划（模型 JSON 里的 `turn_plan` 在校验前丢弃，偏差 X9）；主回复失败时计划随 `AssistantUnavailableError.plan_outcome` 带出。
  - `_plan_tool_names`：计划的房态、订房、房型项映射出的工具只增加开放；旧规则命中的工具仍强制调用（`forced_tool_names`）。
  - `_merge_item_knowledge`：每个本店事实项单独检索并与整句结果合并去重，点名房号经 `find_property_by_room` 映射后按该房检索。
  - `_selection_evidence_plan`：主调用回传 `evidence_selection`，逐项经 `verify_selected_evidence` 核验；不回传时回到现行证据计划。
  - 无日期问价：删除整轮早退，改为只对房价追加澄清分项、本轮不开放参考价工具；计划确认整轮只有无日期问价时仍直接追问（偏差 X8）。
  - `_plan_property_specific`：计划成功且没有本店事项时，「你们」不再单独把问题判成本店专属。
- `src/homestay_bot/services/knowledge_evidence_policy.py`：
  - 新增 `verify_selected_evidence`：编号必须是合法候选；有效期不覆盖目标日期的条目不合法（偏差 X13）；跨越生效边界交回现行计划分段；只对客人问到的钟点或收费，在「回答条目 ∪ 问法点名同一主题的候选」里查冲突（偏差 X14）；保留指令注入与长度规则。
  - `_build_evidence_plan_for_period`：特殊时期政策与平时政策对同一属性矛盾时以特殊时期为准（D6，偏差 X4）。
- `src/homestay_bot/services/knowledge_service.py`：`retrieve`/`retrieve_detailed` 新增 `reserved_property_slots`（D8：3 条）；新增 `PropertyRoomRepository` 与 `KnowledgeService.find_property_by_room`。
- `src/homestay_bot/application.py`：`SessionKnowledgeRepository.find_property_by_room`（按 `PropertyProfile.room_number` 查启用房源）。
- `src/homestay_bot/services/model_budget.py`：规划超时、输出与正文预算。
- `src/homestay_bot/services/runtime_clients.py`：生产装配开启 `plan_turns`。

### 第三批：统一任务写入口（Spec §2.5）

- `src/homestay_bot/services/answer_policy.py`：新增 `TaskResolution`、`resolve_task_request` 与确认话术常量。
  - 撤回按 `withdraws` 与位置判定：在后的撤回取消被指向的申请；撤回在前且本计划内没有更早申请时表示对象不在本计划；有更早申请却关联不明、撤回项位置失效时转确认。
  - 历史、否定、静态咨询不登记；只有不明确项且词面像申请时转确认（偏差 X5）。
  - 规划失败：服务类不登记，词面命中回 D13 话术；设施有故障信号时给安全提示并请客人确认（D14）。
  - 任务类型：多事项或订房为特殊服务，单个设施故障为维修。
- `deepseek_client._validate_decision`：是否保留 `task_suggestion` 改由 `resolve_task_request` 决定。
- `src/homestay_bot/services/conversation_service.py`：
  - `_record_task_suggestion`：登记只由统一判定决定，类型取判定结果；撤回时 `_notify_withdrawn` 通知管家（D11）。
  - `_handle_facility_issue`：新增 `plan_outcome`；判定不登记时只给安全提示与确认，不出现「已提交」。
  - `_process_model_reply_body`：模型可用与不可用两条设施分支都按计划判定当前故障；主回复失败时取异常里的计划，摘要不一致按无计划处理。
- `src/homestay_bot/services/guest_reply_policy.py`：`prepare_facility_advice_reply(safety_tip=...)` 在建议没写停用时追加本地安全提示（偏差 X16）。

### 第四批：软判定与接管（Spec §2.3、§2.6）

- `answer_policy.resolve_handoff_reason`、`agitated_cleared_by_plan`：只有 agitated 可按计划复核，退款、平台投诉、议价保持确定性；各出口（即时、合并、后台、`_validate_decision`、模型后切人工）都调用它。
- `ConversationService._plan_with_released_lock`：先经提交边界释放活动锁，规划后重新加锁，模式、原生人工或新活动有变化时丢弃本轮。
- `handle_message`：只命中情绪词的客诉、`HUMAN_ACTIVE` 下只命中情绪词、无关判定（非合并模式）改为登记合并作业，不在请求里规划。
- `process_debounced_message`：情绪词客诉、`HUMAN_ACTIVE` 情绪词、无关判定在作业内规划复核；计划随最终任务载荷 `turn_plan` 传递。
- `process_recorded_message`：`HUMAN_ACTIVE` 下只命中情绪词时规划复核，继续主回复前再提交一次释放锁。
- `_process_model_reply_body`：计划 `current_hazard` 而词面未命中时升级完整紧急处置，`possible_hazard` 给可能危险提醒；只升不降。
- `application.py`：`_deferred_message_from_payload` 还原 `turn_plan`；后台作业的业务会话注入提交边界 `session.commit`。
- `turn_plan.PLANNER_PROMPT_ZH`：危险口径与主模型提示一致（普通停电、跳闸不是触电，偏差 X15）。

### 门禁运行器（与线上同序）
