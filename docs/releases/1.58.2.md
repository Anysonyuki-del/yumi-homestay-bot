## 改动清单

下表省略公共前缀 `src/homestay_bot/`。

| 改在哪里 | 改前 | 改后 |
| --- | --- | --- |
| `services/human_session.py::HumanSessionService.on_servicer_ended` | 会话处于人工模式就响应「结束聊天」事件 | 必须是管家经按钮接入、仍在原生人工接待的会话（`native_session_active`）才响应 |
| `routes/wecom_callback.py::WeComCallbackService.verify_and_enqueue` | 验签通过，但不是客服事件或卡片点击的，一律返回 401 | 其他应用事件直接应答成功，不入队；客服事件缺少 Token 或客服账号时仍拒绝 |
| 企业微信后台（配置，非代码） | 应用「接收消息」URL 指向已失效的临时隧道地址 | 用户亲手改为生产回调地址（助手修改被权限规则拦下），Token 与 EncodingAESKey 未变 |

## 改动凭据

| 改动 | 依据 |
| --- | --- |
| 旧结束事件 | 1.58.1 测试号审计：14:21:21 接管（`manual_request_or_media`，未接入），14:21:32 交还（`servicer_end`）；日志「会话状态提示发送失败：WeComApiError」。用户那次「结束聊天」发生在 13:3x |
| 回调地址 | 用户反馈「点接入人工没反应」；生产日志 72 小时内没有任何回调请求，jobs 表里没有回调产生的同步任务；企业微信后台显示的 URL 为临时隧道域名。用户要求「你自己操作并优化配置」，修改地址被权限规则拦下，由用户亲手保存 |
| 不处理事件直接应答 | 回调地址恢复后，员工进入应用等事件也会推送过来；返回失败会被企业微信按失败重推 |

## 风险与未覆盖

- 如果管家不通过按钮、而是在企业微信里直接从待接入池接入会话，「结束聊天」不会被本系统识别为交还；机器人仍会在客人下一条消息时恢复回复。目前待接入池不使用。
- 回调恢复后，客人消息从定时补拉改为实时推送，补拉仍作为兜底保留。
