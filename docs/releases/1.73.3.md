## 部署前置（复审 M1）

- Compose 对整个文件做变量插值，部署脚本的 `docker compose build api` 在缺少 `POSTGRES_PASSWORD` 时会失败。生产 `.env` 发版前没有这一项。
- 发版前只读核对结果：生产数据库角色仍在使用旧 `compose.yaml` 里的固定口令；运行中的 PostgreSQL 容器以同一口令初始化；`DATABASE_URL` 的密码段解码后与它一致。
- 处理：在生产 `.env` 追加 `POSTGRES_PASSWORD`，值等于当前口令，不改变任何凭据。部署脚本用 `up -d --no-deps api`，不会调和 PostgreSQL 服务；另用 `docker compose config --hash postgres` 核对追加前后哈希不变。
- **遗留风险**：生产数据库口令仍是曾经提交进仓库的值。PostgreSQL 没有映射宿主机端口，只在容器网络内可达，但仍建议另排维护窗口按 README 轮换。本次不做。

## 风险与未覆盖

- 「结果未知」的图片不再自动补发，改由管家核实。如果平台实际没收到，客人会少一张图，直到管家补发。这是有意的取舍：重复发送无法撤回，漏发可以补。
