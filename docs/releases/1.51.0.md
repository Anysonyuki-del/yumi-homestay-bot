### 顺带修复

1.48.0 F6 给知识列表加了按房间筛选，路由会传 `room`，但生产装配的 `SessionKnowledgeAdminService.list_all` 不接受这个参数，打开知识列表会报错。原测试只直接测了底层服务，没覆盖生产装配。已补上参数和回归测试 `test_session_service_passes_the_room_filter`。

## 改动凭据

| 改动 | 依据 |
| --- | --- |
| 全部功能 | 用户问「能给客人发图片吗」，确认 Spec（「可以」），并指示「先做好功能」，图片内容以后再录 |
| 只收 JPG、PNG | 企业微信临时图片素材只支持这两种格式；原 Spec 写的 webp 能存下却发不出去 |
| 5 条上限 | 企业微信客服每次最多回 5 条（Spec D1） |
| 非文字消息不自动重发 | 原重发逻辑直接取消息正文按文字发送，图片消息的正文是占位符 |

## 风险与未覆盖

- **显示效果只能真机确认**：企业微信接口受理图片不代表客人手机上显示正常；二维码裁剪后能否扫出，也要真机确认（Spec 验收第 5 条，录入图片后做）。
- **条数额度**：图片占企业微信的回复条数。已用 5 条上限控制，超出只记日志。
- **欢迎图在全部文字之后**：欢迎语和答案是同一条文字，欢迎图排在它后面、知识配图前面。
- **停用条目保留文件**：后台只有停用，没有删除知识条目；停用后不附图，文件保留。直接删库时文件不会自动清理。
- **本版没有录入任何图片**：上线后行为与 1.50.0 相同，直到后台上传图片。

## 回滚

回滚代码到 `v1.50.0` 并执行 `alembic downgrade 0032_knowledge_triggers`，只重建 API 容器。降级删除配图记录和欢迎图片列，私有目录里的图片文件保留，不影响旧版本运行。
