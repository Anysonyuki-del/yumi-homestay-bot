## 改动凭据

| 改动 | 依据 |
| --- | --- |
| 全部 | 用户原话：「客户记忆摘要页面过于繁琐，七天内记忆重复了很多我不需要知道的内容。结构化客户记忆也不便使用，重新审查该功能」。审查结论与 4 项建议（接手要点、推断不入库、页面只读加折叠、测试号旧数据清掉）用户回复「照你的来。直接全部做完」 |
| 审查依据 | 生产库只读核对：当时只有测试号有摘要和记忆。七天内摘要复述了停车、上楼、地址、实名登记的标准答复，「客人要求打八折」埋在末尾且没写处理结果；5 条结构化记忆全是模型推断的待审核候选（「客人询问民宿具体地址」等），待审核候选不会提供给回复模型 |
| 受控主题清单进提示词 | 本版红测发现：客人说「我对海鲜过敏」、模型报 `food_allergy`，因主题不在受控清单里无法核验而被丢弃；模型此前从不知道有这份清单 |

## 风险与未覆盖

- **记忆范围变窄**：只有 7 类受控主题能生效（饮食忌口或过敏、楼层、床型、安静、联系方式、猫狗名字）。同行老人儿童、发票需求等不在清单里，改由「接手要点」记录，不会长期保留到下次住宿。
- **要点质量依赖模型**：提示词约束了三类内容和条数，但没有本地硬校验；模型仍可能写进标准问答。
- **旧数据**：测试号现有 5 条候选在发布后随「清空测试数据」清掉。真实客户目前没有摘要和记忆，不涉及迁移。

## 回滚

回滚代码到 `v1.55.0`，只重建 API 容器；本版无迁移。本版不再产生的候选记录，回滚后也不会补回。
