## 改动清单

| 改在哪里 | 改前 | 改后 |
| --- | --- | --- |
| `src/homestay_bot/tools/reply_regression.py`：`resolve_scope`（新增）、`gate_verdict(scope=…)`、`gate --only` | 门禁总是跑全部场景 | `--only` 接受逗号分隔的场景编号或类别，写错直接报错。判定只看范围内场景：范围外的不退步场景没跑不算退步，范围外的已知未通过也不会被纳入。计数里新增总场景数和是否按范围运行 |
| `scripts/release/reply_gate.sh` | 只要回复链路文件有改动就全量 | 新增 `REPLY_GATE_SCOPE`：`all`（默认）、`tourism`、自定义场景 / 类别、`skip`。`tourism` 取联网类场景，加上上一次门禁结果里 `traces` 中实际出现过 `tourism_search` 的场景。非全量必须给 `REPLY_GATE_SCOPE_REASON`，摘要里写明范围、场景数和理由 |
| `AGENTS.md` | 本地全量按改动范围判断 | 扩展为：跑任何测试（单元、全量、真实门禁、测试号验收）前先判断有没有必要；写明门禁范围的用法，以及哪些情况必须全量 |

## 改动凭据

| 改动 | 依据 |
| --- | --- |
| 全部 | 用户原话：「这种改动是否不应该全量真实跑？审查一下是否有必要」，以及「改动门禁，所有的改动跑测试之前都先问自己有没有必要再去测试」。审查结论见 1.59.1 现场追加：1.59.1 只影响联网回答，154 个场景里约 11 个相关 |
| `tourism` 范围的取法 | 1.59.0 门禁结果中，`traces` 含 `tourism_search` 的场景除了两个联网类别，还有 `K-距离-D`、`K-距离-C`、`K-公区-D`、`L-住处`、`L-火车站`。只按类别圈会漏；本机按 v1.59.1 试算得到 11 个 |

## 风险与未覆盖

- 范围由执行者判断，判断错了会漏掉退步；因此默认仍是全量，非全量必须写明理由，并在发布记录里可追溯。
- `tourism` 依赖本机 `.stage` 里上一次门禁的结果文件；找不到时只按类别圈，漏掉距离、位置类场景的风险更高。

## 回滚

回滚代码到 `v1.59.1`，只重建 API 容器；无迁移。
