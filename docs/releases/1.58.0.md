## 改动凭据

| 改动 | 依据 |
| --- | --- |
| 原生会话流程 | 用户要求：客人要人工时，企业微信要能直接跳到这位客人的对话，而不只是「查看对话」；要验证微信客服的会话状态。2026-09-29 测试号实测：人工接待时机器人发消息被拒（95018）；不能改回智能助手接待（95016），结束后客人下一条消息机器人恢复；员工在企业微信里的回复记为员工消息；切换返回的 msg_code 能给客人发提示；「打开会话」接口不支持微信客服客人 |
| 管家点按钮确认接入 | 用户原话：「何时转人工应该由管家来确认，点击按钮后就会接入人工」 |
| 交还按钮与「结束聊天」都能交还 | 用户实测接入后「管家这边没有交还ai助手按钮」，确认会话里有「结束聊天」，并要求两条路都做 |
| 客人提示文案 | 用户否决「管家暂时离开」的说法；三句文案按用户「按q1的基准来做」确定 |
| 通知前先整理要点，去掉「转人工」原话 | 用户原话：「应当整理客户需求让管家快速理解」；用户同意 Q3 的卡片方案 |
| 「我已经发起过咨询了，现在由你继续提供服务。」不处理 | 用户截图确认，这是企业微信在会话由智能助手转人工时以客人名义自动插入的固定文字，接口不能去掉 |

## 风险与未覆盖

- **只有企业微信客户端能用按钮**：通过「微信插件」收消息的员工看不到按钮卡片。
- **接入人必须是这个微信客服账号的接待人员，且状态为「接待中」**：目前只加了一位值班员工，其他人点「接入人工」会看到「接入失败」。
- **原生会话期间机器人完全静默**：紧急情况的后续安全提示也不再由机器人发出，由已接入的管家负责。紧急情况和客诉仍不会自动交还，需要管家点交还或「结束聊天」。
- **卡片里的时限提示对紧急情况和客诉不准**：这两类不会自动交还，卡片上仍会写「5 分钟内没有管家接入，将交还机器人」。这沿用了 1.57.0 的判断口径，本版未改。
- **企业微信自带的提示无法去掉**：接入时，管家那边会看到企业微信以客人名义插入的「我已经发起过咨询了，现在由你继续提供服务。」。
- **msg_code 有时效**：如果「结束聊天」事件处理延迟过久，结束语可能发不出去；会话照样交还，客人下一条消息机器人正常回复。
- **卡片发送晚几秒**：发送前要先调模型整理要点，卡片会比客人消息晚几秒到。

## 回滚

回滚代码到 `v1.57.0`，只重建 API 容器；本版无迁移。回滚前，如果有会话仍处于原生人工接待，先让管家点「结束聊天」，否则旧版本的机器人消息会被平台拒绝。
