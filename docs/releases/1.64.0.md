## 风险与未覆盖

- 没有在真实百居易上走过 A1–A3 与新的建单流程：生产当前没有审批单，开发过程也没有调用外部接口的授权。
- 迟到的旧一轮结果被丢弃时只记日志，没有写审计或通知员工；如果旧一轮其实在百居易建单成功，多出的订单需要人工发现。
- A1 不核对订单号，这是用户的决定：订单号填错会误标为已预订，只能依靠确认框和审计事后追查。
- 已知范围外风险：其他 `begin_nested` 在 SQLite 下的提交语义问题，生产 PostgreSQL 不受影响，另立项处理。
