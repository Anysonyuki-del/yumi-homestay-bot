## 改动清单

下表省略公共前缀 `src/homestay_bot/`。

| 改在哪里 | 改前 | 改后 |
| --- | --- | --- |
| `services/knowledge_service.py::PROPERTY_TOPICS`（「电梯」主题） | 只认「电梯 / elevator」。「401要爬几层楼啊」识别不到本店话题，交给模型自由回答，时常漏掉「四楼、只能走楼梯」 | 另外认「房号或房间 + 几楼 / 几层 / 楼层 / 爬楼 / 楼梯」（房号后面跟「元 / 块」的不算）。不带房号的「爬楼」「楼梯」只用于检索召回，不参与本店话题判定：「黄鹤楼要爬几层」仍按旅游问题处理 |
| `services/knowledge_evidence_policy.py::_ATTRIBUTE_QUESTION_PATTERNS`（位置） | 位置属性只认「几楼 / 楼层」等，「几层」「爬楼」判不出在问什么，证据门保守地回「尚未确认电梯信息」 | 补「几层」「爬楼」。审核答案里的「四楼 / 4层」算作位置证据，按审核知识作答 |
| `tests/fixtures/guest_reply_scenarios.json`（F-跳闸） | 必含说法「停止使用 / 不要再 / 配电箱」 | 补同义说法「停用」；禁用片段不变；`_synonym_expansion` 记录依据 |

| 改动 | 依据 |

| 楼层问法 | 1.46.0 门禁第一次运行，K-电梯-C（「401要爬几层楼啊，箱子很重」）3 次里有 2 次漏了四楼和只能走楼梯。我汇报为真实回答缺口，用户指示「发布 修」 |

## 风险与未覆盖

- 英文「Which floor is room 401 on?」仍不识别为楼层问题（`which floor` 在旅游问题里太常见，没加）。
- 生产上现在只有 3 条已启用知识（入住退房），没有楼层、电梯知识。这次改动在生产上的效果是：识别成楼层问题后没有审核知识作证，会回「尚未确认」，不会再由模型自由发挥。要让客人得到实际答案，需要在后台补一条楼层与电梯的知识。
- 「停用」补进判定词表，只放宽了这一组必含说法，禁用片段不变。

回滚代码到 `v1.46.0`，只重建 API 容器；本版无迁移。
