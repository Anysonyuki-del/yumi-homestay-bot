## 风险与未覆盖

- compose 没有配置日志轮转，容器重建后日志会丢失；分析前先导出。
- 模型耗时波动大，至少攒 30 条普通回复，看中位数和 P90 后再下结论。
- `since_sent_ms` 依赖企业微信时间戳，精度只到秒，而且两边时钟不同，是近似值。
- 紧急情况后续、客诉、转人工这些不进 `_process_model_reply` 的路径，没有汇总行。
- 与边界 Spec 重构冲突：`respond`、`_process_model_reply` 正是它改动最多的函数，合并时需要在新版本里补回结果标记。

## 回滚

只回滚代码到 `v1.40.1`，只重建 API 容器；无迁移。
