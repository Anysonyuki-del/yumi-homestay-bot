## 改动及依据

### 1. 紧急分类豁免只覆盖可识别的非现场范围

- **文件与符号**：`src/homestay_bot/services/emergency_service.py`
  - `EmergencyService._noncurrent_mention`：重写；签名改为接收句子、句末是否问号、分句与命中区间。
  - 新增 `EmergencyService._segments`：句子与分句切分。分句口径与旧版相同，额外保留整句与句末问号。
  - `EmergencyService.classify`：改为按句子与分句遍历，危险类别顺序、可能危险判定与处置文案不变。
  - 新增模块级句式常量（`_INQUIRY_MARKER`、`_ALARM_DEVICE`、`_HYPOTHETICAL_MARKER`、`_QUOTED_TEXT` 等），只用来限定豁免区间。
- **改前**：开头的「燃气灶…吗 / 报警器…在哪 / 怎么赔」检查与末尾的「在哪里 / 安全规定」检查对整句生效；假设、引用、`what is/are` 前缀只要出现在命中之前就豁免。同一句里正在发生的另一处危险被一起放过。
- **改后**：
  - 设备咨询只豁免「燃气灶 / 煤气炉」中的燃气词，且整句为疑问、没有燃气现场信号。
  - 报警器、灭火器位置咨询只豁免设备名区间内的命中，正在响等现场信号不豁免。
  - 安全规定咨询只豁免直接修饰「安全规定 / 政策 / safety policy」的危险词。
  - 假设只豁免条件结束边界（后果询问词或句末问号）之前的命中，没有边界不豁免。
  - 引用只豁免引号内的命中，没有引号时到「是什么意思」等释义询问词为止，都没有不豁免。
  - `what is/are` 不再单独构成豁免；「怎么赔」不再豁免。
  - 否定检查（标记紧贴命中）不变。
- **依据**：`docs/specs/2026-10-07_emergency-exemption-scope-spec.md` v4（三段已于 2026-10-07 由用户确认；D1 疑问语气的现场描述判确定危险、D2「怎么赔」不豁免、D3 并入第一批）。复现证据：Spec §1.2 所列 14 句（含 Codex 复审 G4、V3-R3、V4-R4、V5-R1 提供并经本地复核的样例），当前代码均判错。

### 2. 真实模型门禁判定修正（P0）

## 风险、未覆盖与回滚

- **误报方向**：收紧豁免后，没有结束边界的悬空假设（「如果着火」）、无引号且无释义询问词的引用，都会判为危险。这是按安全优先有意接受的误报。
- **规则上限**：豁免边界仍是确定性句式规则，只消除「豁免越界」这一类缺陷。词面没有命中的危险（「窜白烟」「报警器在哪里一直在响」）留待第四批语义补漏。
- **门禁口径变化**：本版之后的门禁通过数不能与 1.68.0 的 107/47 直接比较。
- **回滚**：恢复部署前备份的源码与旧 API 镜像，仅替换 API；不涉及数据库。
