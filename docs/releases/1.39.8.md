## 改动凭据

- **用户原话与决定**：
  - 「修语病，给出spec」；
  - 「这个修复是只针对这一个问题，还是泛用性的修复，我希望不要每次出现类似的问题都需要修复」，据此从 R1 改为结构性的 R2；
  - 「旅游和闲聊这种段落也需要排版，一起给出修改建议」；
  - 「开始」。
- **真实样本**：测试号的三条生产回复，只读取证。设施回复条件写反且拼接别扭；天气回复四个小节挤成一段；路线回复行程不分段、达 1817 字节。见 Spec §1.1。
- **根因证据**：`sanitize_guest_reply` 逐句 `strip()` 后直接拼接。句中换行得以保留、句号后的分段全部丢失，与样本的现象一致（Spec §1.2）。

## 风险与未覆盖

- 模型本身不分段时，排版步骤不会拆开行程正文，这部分依赖提示词。
- 不对任意语病做确定性检测（Spec §3 D4）。
- 本版发现回复只按 1500 字符截断、没有企业微信 2048 字节保护，已单列给用户决定，由 1.39.9 处理。
- 回归教训：提示词改动会改变输出结构，依赖位置的固定规则（如 `startswith`）会随之失效。

## 回滚

只回滚代码到 `v1.39.7`，只重建 API 容器；无迁移。
