## 2. 当前代码约束

- `src/homestay_bot/domain/models.py::KnowledgeEntry` 支持分类、双语问答、关键词、启用状态及修改人。
- `src/homestay_bot/routes/knowledge.py::KnowledgeAdminService.create` 固定 `is_enabled=True`，且内部提交事务。不能直接把含 `is_enabled` 的 JSON 展开传入：既不支持停用草稿语义，又会重复传参。
- 同文件 `set_enabled` 是另一次提交。禁止采用“新建启用后马上停用”录入未审核资料，中间存在被检索的窗口。
- 同文件 `_add_audit` 的现有审计只记管理员、动作、条目 ID，不复制正文。
- `src/homestay_bot/repositories/knowledge.py::SQLAlchemyKnowledgeRepository.list_active` 只读取启用条目。保持草稿从第一次提交起就停用，才能让用户在后台审核而不进入正式回复证据。

这些结论须在接手时按最新源码复核。JSON 是数据草稿，不是现有批量导入接口的请求格式。

## 3. 最小执行方案

优先复用接手时已有的、支持初始停用及审计的录入工具。若仍不存在，先按项目 Spec 流程确认一个一次性本地导入工具；不要为了 40 条资料开发通用导入平台、上传页面、新审批系统或新数据表。

最小文件范围：两份现有内容文件、一个按仓库约定放置的导入工具、一个对应的事务/重复导入测试。原则上不改检索、模型客户端、数据库结构或后台现有新建行为。新增工具的具体路径在接手核对项目目录后确定，再写入实施计划。

导入工具要求：

1. 默认只做预览，展示目标环境标识、输入文件摘要、数量、分类汇总及重复冲突数；不打印凭据、连接串、原始正文。不默认连接生产。
2. 严格接受现有七个内容字段：`category`、`question_zh`、`answer_zh`、`question_en`、`answer_en`、`keywords`、`is_enabled`。校验类型、非空、分类长度、问题重复，且所有记录必须停用。
3. 使用现有数据库连接方式和 SQLAlchemy 模型。在一个事务内插入所有新条目，初始状态始终为停用；填写真实有效的操作管理员 ID，遵循现有审计动作及最小字段约定。不伪造管理员。
4. 执行前比较现有条目。按现有标准化逻辑比较分类及双语问题：完全相同的已导入内容跳过；同身份但正文或关键词不同的列为冲突并停止写入。不覆盖已有审核修改，不把启用条目强制停用。不为单次导入新增通用去重框架。
5. 预览后、写入事务内重新检查冲突。工具限定管理员串行运行，不能声称在无数据库唯一约束时支持并发导入。
6. 输出本轮新建条目 ID、跳过数量和输入摘要作为私有执行记录，便于追踪；出现任何写入错误则整批回滚。回滚不能按类别或标题批量删除原有知识。

占位内容可以作为停用草稿存放，不能自动启用。不要为填满答案编造实际地址、商户、楼层、距离、设施或费率，也不要把测试夹具当真实事实来源。
