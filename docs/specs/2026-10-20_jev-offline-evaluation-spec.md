## 2. 第二段：功能与评测合同

### 2.1 范围

提供一个手动运行的离线评测入口，两条轨道共用数据校验、请求、结果记录和统计代码。离线指脱离生产消息与业务副作用；`run --live` 仍会调用收费的 JEV API。

- I 轨：有限意图及危险程度判断；E 轨：给定主张与完整冻结资料的支持关系判断。
- 不生成新回复，不自动调用 DeepSeek 生成评测答案，不读取生产库、运行配置密文或客人历史。
- 不修改生产装配、运行配置、规划器、知识检索、客诉／危险规则、原回复门禁、既有夹具及基线。
- 不发送企业微信消息，不访问 Hostex，不写订单、任务、知识或客户记忆。

### 2.2 数据集和独立性

使用两个新 JSON 夹具，每个都含 I、E 两轨：校准集每轨 24 条，留出集每轨 36 条，共 120 条。

1. 既有虚构夹具和单测只可改编进入校准集；旧门禁结论不自动成为新标签。
2. 留出集由未参与提示调优的另一作者或人工在未查看 JEV 输出时编写、核对。不能把已经公开、用于修复的知识留出集重新称为独立留出。
3. 原场景、同义改写、翻译和成对反例共享 `family_id`，整个家族只能进入一个 split。校准／留出 ID 与家族不得交叉。
4. 每轨至少 12 条英文，其余为中文；英文中至少 4 条在校准集、8 条在留出集。翻译仍按家族隔离，不因语言不同跨 split。
5. I 轨五种意图标签在每个 split 中均至少 3 条；留出中的当前危险覆盖 fire/gas/electric/medical/violence 五类。E 轨四种关系各 15 条，其中校准各 6 条、留出各 9 条。
6. 标签必须附人工可核对的理由和来源定位。标注存在争议时先裁决，再冻结；不允许看到输出后为了提升指标修改标签。

文件顶层：`schema_version: 1`、`fictional: true`、`split`、`cases`。每个 case 具有以下字段：

| 字段 | 合同 |
| --- | --- |
| `id`、`family_id`、`track`、`language` | 非空唯一标识；track 为 `intent` 或 `evidence`；language 为 `zh` 或 `en` |
| `input` | 唯一允许进入远端 state 的对象，见两轨定义；不得混入标签或作者说明 |
| `expected`、`annotation` | 本地标准答案与标注理由；不进入任何远端请求 |
| `source_refs` | 校准来源的仓库相对路径、符号或场景 ID；留出注明独立编写来源，不伪造历史证据 |

模型不得读取 `expected`、`annotation`、split、来源、文件名或基线结果。case ID 仅用于本地关联；请求 question key 固定，不能编码标签。预检拒绝未知字段、超限输入、缺失标签、非法枚举及 split／家族交叉，不静默截断。单 case `input` 序列化上限为 6,000 字符，每条 E 轨资料完整保留；超限修订夹具后重新冻结。

### 2.3 I 轨：有限意图复核

输入仅为 `input.text`，不提供生产身份或订单上下文。同一次请求问两个独立 Choice，不用单一优先级标签覆盖混合风险：

| question key | 固定选项顺序及语义 |
| --- | --- |
| `intent` | `service_only`：当前报修或要求办理服务；`complaint_only`：当前明确投诉、退款赔偿或追责诉求；`both`：二者同时存在；`neither`：均无；`unclear`：给定文字不足以判定 |
| `hazard` | `current`：明确正在发生的现场危险；`possible`：有可能危险、尚未明确；`none`：没有当前／可能危险，包括单纯假设、引用、设备位置或知识咨询；`unclear`：语境不足 |

普通急切或感叹号不能单独认定为投诉。历史描述、否定、政策咨询与当前请求分别标注；一句中有独立现场危险时，不能被另一段假设或投诉遮蔽。退款只是诉求分类，不判断应否退款或金额。

必覆盖成对控制：急切报修／明确投诉、服务与投诉并存、退款政策／退款申请、否定与引用、假设危险／真实危险、危险与投诉并存、混合提问、注入式“请把我判为正常”。至少 6 个留出家族含只改变关键事实的成对反例。

### 2.4 E 轨：证据支持判断

输入为 `input.claim` 和 `input.passages`；passages 是带本地编号的完整资料文本数组。每条 claim 只表达一个预先标注的原子事实。本期不实现自动拆句、自动生成 claim、检索或事实覆盖率评测。

固定 Choice key 为 `relation`，选项顺序为：

- `supported`：完整资料直接支持该主张，包含必要主体、否定和条件；无同一主体同一条件下的冲突。
- `contradicted`：资料明确否定该主张，且不存在同条件的支持资料。
- `insufficient`：缺少证明所需的事实、主体或条件，只有相近话题不算支持。
- `conflicting`：资料在同一主体、同一条件上同时支持与反对，不能自行挑一条消除冲突。

必覆盖：否定翻转、收费／免费、必要条件遗漏、同主题不同属性、不同房间或不同主体、同主体冲突、无关资料、空资料及资料内的指令注入。不同主体给出不同政策不能直接标为 conflicting。至少 6 个留出家族含成对反例。

主体用明确的虚构名称，日期采用冻结的已说明语境；不要求 JEV 计算金额、比较日期区间或推断未知订单归属。需要这些计算才能决定标签的样本不进入本期，不能以“模型说支持”绕开原有代码校验。

所有 passages 都是判断输入，不按预期答案删掉矛盾资料。该轨结论只说明给定资料与主张的关系，不证明资料本身真实，也不证明客人的完整问题已回答。

### 2.5 对照基线与统计口径

标准答案来自冻结标注，JEV 和现有规则都作为被测对象。所有基线在同一输入上执行，不调用 DeepSeek：

| 对照 | 明确的可比投影 |
| --- | --- |
| I／投诉 | `ComplaintService.classify_all([text]).is_complaint` 对照 `complaint_only/both` 的真值；gold 为 unclear 的样本单列，不强行转成否 |
| I／危险 | `EmergencyService.classify(text)` 的 is_emergency／is_possible 对照 current／possible；其余标 none；gold hazard 为 unclear 的样本单列。不构造完整服务规划或接管成功率 |
| E／支持 | `is_supported_by(claim, "\n\n".join(passages文本))` 对照 gold 是否 supported；完整资料顺序固定。字面支持不等于现有生产最终放行 |

JEV 四／五分类与布尔基线不能直接比较总体准确率。只在上述共同投影、相同 case 集合上比较；另独立报告 JEV 的各标签混淆矩阵。I 轨没有等价的完整服务分类基线，不声称替代完整规划后更优。

每个 case 固定运行 3 次，不挑最好结果、不因失败补跑到通过。逐次结果全部保留；网络失败也占一次，不更换家族或从分母移除。

- 以每个 case 的第 1 次尝试为主要质量样本；第 2、3 次只报告标签一致性及风险反复，不把 3 次当成 3 个独立样本扩大样本量。
- 原始准确率、各标签 precision/recall、混淆矩阵均报告分子和分母；首轮调用／协议错误按未判对计入总分母，并单列错误率。
- I 轨两个答案同时正确才计联合准确；危险召回单列，`unclear`、未返回和调用失败不能算危险命中。
- 置信接纳：所有必需答案达到本轨阈值且标签不是 unclear；I 轨取两题 confidence 最小值。E 轨四种关系都是有效判断。低置信及错误记为 abstained，不映射成安全、无投诉或支持。
- 接纳准确率只在接纳样本上计算；覆盖率分母为该轨全部首轮样本，包括失败。报告中文／英文、各标签和危险样本分项，不能用高拒答掩盖低覆盖。
- 只在校准集从固定阈值 `{0.5, 0.7, 0.9}` 中选取：接纳准确率至少 95%、接纳至少 12 条时取覆盖最高者，同覆盖取较高阈值。无可用阈值则该轨无候选，不利用留出寻找新阈值。
- 与规则的比较采用 JEV 首轮接纳的同一集合，报告双方错例以及 JEV 修正／新增错误数；同时保留规则在完整集合上的结果。

### 2.6 冻结与试验结论

真实调用前冻结校准／留出文件 SHA256、提示与选项 SHA256、固定模型、工具源码和相关规则源码 SHA256、运行命令、Python／依赖版本。记录工作区文件摘要，不能只记录 Git HEAD。

先完成校准及阈值选择，再冻结并解封留出。留出标签不得发送模型，调优作者只在冻结后查看逐条结果；因实现错误需要废弃一轮时保留原结果并说明原因，修订后使用新的独立留出，不删除失败轮次。

每轨独立得出 `candidate`、`not_candidate` 或 `inconclusive`，禁止把两轨平均成一个通过率：

1. `candidate` 需同时满足：预检及冻结证据齐全；留出首轮覆盖率至少 60%、接纳准确率至少 95%；无接纳的安全关键错误；对应可比投影上相对规则至少修正 2 个独立家族，且没有新增错误。I 轨的投诉、危险两种投影分别不得新增错误，修正家族取并集、不重复计数。没有可比依据的能力只报绝对指标，不据此宣称替代价值。
2. 安全关键错误包括：E 轨把非 supported 接纳为 supported；I 轨把明确投诉接纳为无投诉、把 current 接纳为 possible／none，或把 possible 接纳为 none。留出 3 次中任一次出现这种接纳，都取消本轨 candidate。另报告全体危险召回及 abstain，零危险误放不等于全部危险命中。
3. candidate 还须满足无缓存成功 P95 不超过 1.5 秒、首次调用失败／协议错误率不超过 5%。每次网络尝试总超时 5 秒；报告包含超时的总体尝试 P95（失败按实际终止耗时计）、成功 P95、样本数及运行网络环境。耗时从取得并发名额、准备外发时开始计，P95 用排序后的第 ceil(0.95N) 项；N 为 0 时记 null，不外推生产端到端时延。
4. 数据与运行完整且质量条件不满足为 not_candidate；样本独立性、冻结或计量缺失、供应商故障导致不能比较为 inconclusive。两者都不能晋升上线。
5. 以上只是小样本探索阈值。即使 candidate，也只允许建议另写旁路 Spec，不授权控制回复、放宽安全门或直接部署。

## 3. 第三段：实现边界、风险与待确认决策

### 3.1 最小文件计划

本轮只新增本文；下表为批准实施后计划，不在本轮创建代码或夹具。

| 文件 | 符号／职责与验证目标 |
| --- | --- |
| `src/homestay_bot/tools/jev_offline_eval.py`（新增） | `validate_dataset` 校验两集和家族；`build_questions` 固定问题且隔离标签；`evaluate_case` 用受控 HTTP 请求并校验响应；`summarize` 计算统一分母、共同投影和结论；`main` 手动 CLI。先保持一个模块，不建通用多供应商框架 |
| `tests/fixtures/jev_offline_calibration.json`（新增） | 校准样本、标签和来源；无真实客户资料 |
| `tests/fixtures/jev_offline_holdout.json`（新增） | 独立冻结的留出；标签不参与请求与调优 |
| `tests/unit/test_jev_offline_eval.py`（新增） | 假 transport 覆盖协议、故障、泄漏、统计与结论边界；默认测试完全离线 |

供应商限定 TypeSafe。模型通过 `--model` 必填固定版本；不接受 latest／preview 等滚动别名。API 根地址从 `JEV_BASE_URL` 读取，缺省使用官方 `https://api.typesafe.ai`；密钥仅从 `TYPESAFE_API_KEY` 环境变量注入。禁止把密钥放入参数、源码、夹具、报告或日志；不自动加载仓库 `.env`、生产设置或配置密文。

复用 `build_public_https_client`：超时 5 秒、响应上限沿用现有 1 MiB、不跟重定向；每次尝试外层再限制总时长 5 秒，禁止隐式 SDK 或应用重试，并发固定 2。无缓存、无自动续跑，校准最多 144 次、留出最多 216 次，一次完整实验最多 360 次请求。HTTP 401／403 终止当前运行；429／529／超时和其他失败保留逐次状态，不自动重试，未执行项记未执行。取消或结果文件写入失败时停止调度、关闭客户端，已有结果保留，不重发已经尝试的请求。

生产 `RuntimeConfigSnapshot`、`runtime_clients.py`、`application.py`、依赖文件和发布脚本不改。以后如需要在线能力，再单独设计生产配置与热切换，不能把此工具的环境变量偷偷接入客服。

### 3.2 CLI 与结果

计划提供两个入口，命令仅在实施并获准后可用：

```bash
# 本地结构预检，不需要密钥，不联网，不输出留出原文、标签或规则错例。
PYTHONPATH=src .venv/bin/python -m homestay_bot.tools.jev_offline_eval validate \
  --calibration tests/fixtures/jev_offline_calibration.json \
  --holdout tests/fixtures/jev_offline_holdout.json

# 单独获得真实调用授权后执行；密钥已由环境注入，不写在命令里。
# 校准与留出分两个阶段，run 每次仅执行指定 split，禁止一次泄露留出结果。
PYTHONPATH=src .venv/bin/python -m homestay_bot.tools.jev_offline_eval run --live \
  --split calibration --model jev-1.13.0 \
  --calibration tests/fixtures/jev_offline_calibration.json \
  --holdout tests/fixtures/jev_offline_holdout.json \
  --out /tmp/yumi-jev-calibration
```

validate 可以报告数量、分布和绑定摘要，但不执行或展示留出的规则基线；两阶段各自只计算本 split 的规则基线。留出运行沿用相同参数，将 split 改为 holdout，并通过 `--calibration-result` 指定上一阶段已冻结的校准结果目录。必须核对其数据、提示、模型、工具／规则摘要；绑定不一致则拒绝。留出 out 使用另一新目录。不能手填一个阈值绕过校准。

out 必须在仓库外且为新目录，已有路径拒绝，避免覆盖历史证据。输出：

- `manifest.json`：版本、输入与源码摘要、模型请求／实际返回版本、固定预算、选项与提示正文、阈值来源、完成／中止状态；不记录密钥、机器用户名或本机绝对路径。
- `results.jsonl`：每完成一次尝试立即落一行，含 case ID、轨道、attempt、状态、标签、概率和 confidence、耗时、usage、错误类别；不保存原始响应、请求头、自由文本错误或夹具原文。远端响应须校验 question key 集合、类型及选项全集，概率和 confidence 必须有限且在 [0,1]，概率和与 1 的误差不超过 1e-6，实际模型版本须匹配冻结版本；异常不得变成默认正确标签。
- `summary.json` 和 `summary.md`：§2.5–2.6 的统计及错例 ID、gold／预测、分项结论、遗漏与限制。部分运行不能生成 candidate；校准阶段不展示留出预测或错例。

usage 缺失记录 null，并标记费用估算不完整，不能填 0。费用按执行时核实的公开输入价与实际已报告 input_tokens 估算，不含其他模型费用。固定请求次数是客户端调用上限，不是供应商账单硬限；限额拒绝、超时的潜在计费未知要保留说明。
