## 2. 第二段：方案

### 2.1 R1：凭据识别（`services/sensitive_text.py`，检测与净化继续共用同一组模式）

- 明确标签后的值整段遮盖，不只遮前缀。值的边界按以下顺序取第一个能匹配的（v2，F3-S1）：
  1. 成对双引号或单引号包围的值：消费到未转义的同类结束引号，允许内部空格与反斜线转义；
  2. 以引号开头但没有闭合：保守遮到该行结束；
  3. 不带引号：连续非空白 ASCII 可见字符（含标点）。
- 标签：
  - 中文：`(门锁|房门|开门|WiFi|Wi-Fi)?密码`、`口令`、`验证码`，可选「是/为」与冒号，后接值；
  - 英文：`door/lock/room/wifi password|passcode|PIN|verification code|security code|access code|OTP`。
- 英文分隔符分两种：
  - 冒号、等号、全角冒号：后面的引号值或任意可见字符串（不带引号时 ≥4 位）都按凭据；
  - 「is」：值必须含数字或符号才算（`password is A!b2C#d4` 遮，`password is needed / changed` 不遮）。
  - 实施边界补齐：无引号的 `needed/changed/required` 状态说明带句末 `.!?` 仍保留；冒号/等号的引号值完整遮盖。`is` 的值去掉外层引号后仍须含数字或符号，带引号的纯字母也可能漏识别。相同拼写也用作真实密码时存在歧义，归入 D-H3 已接受的上限。
  - ponytail：纯字母且用「is」连接的密码（`password is sunshine`）不识别；冒号、等号写法不受影响。
- 中文值同样只认 ASCII 可见字符，所以「密码是多少」「如何获取 Wi-Fi 密码」不受影响。
- 适用面不变：客诉复核、转交原问与标准问题、草稿模型输入、草稿校验、管理员最终提交都走同一函数。

### 2.2 R2：日志里带引号的敏感键（`logging.py`）

- `_SECRET_ASSIGNMENT_PATTERN` 允许键名前后各带一个可选的单/双引号（JSON、repr 写法）。
- 值的引号分支改为识别转义（v2，F3-S2）：反斜线与下一个字符作为一组消费，只由未转义的同类引号结束；引号内的方案词、空格随整个值一起遮盖。不带引号的值保持现有方案词与字段分隔规则。
- 保持现状：`redact_text` 是唯一入口；Uvicorn 访问日志五元参数协议不变；重复过滤幂等；换行与调用栈保留。

### 2.3 R3、R4、R5：同一修复单元——小句范围先核对，取证用剩余语义（`deepseek_client._item_evidence_plan`、`_item_dates`，`item_coverage`）

1. **日期里的数字不是房号（R5）**：`clause_rooms` 先找出小句里所有日期写法（ISO 日期、`X月X日`、日期区间，复用 `item_coverage` 已有的日期模式），把这些区间排除后再识别房号。房号识别、范围核对与剩余处理共用这一结果。保留真四位房号、`room 401`、`220V`、金额的正反样本。
2. **静态小句的日期绑定（R3，Spec fix2 §2.1(2) 已承诺的守卫；v2 按 F3-S3 改为按端点与角色绑定）**：
   - 用已有 `clause_dates` 解析小句日期，每个静态小句得到「绑定日期」或「未绑定」：
     - 小句不点名日期：绑定为该项检索日期范围（现状；真正跨期住宿问政策时仍按有效期分段作答）；
     - 小句点名的入住、退房一对与该项相同：绑定为该项范围；
     - 小句只点名一个日期 d，且 d 落在该项检索日期范围（入住日到退房前一天）内：绑定为 d 当天——静态取证只用 d，不再把整个住宿区间传下去，回复不会混入没被问到的日期；
     - 其余（单日落在范围外、另一组区间、倒置或两段区间、多个日期夹相对日期）：未绑定，记 `scope_unbound`，回未确认，不可转交（D-H1）。
   - 检索范围已经包含 d，所以 d 当天找不到有效资料时记「资料缺失」是真实缺口；范围外的日期一律未绑定，不会被误记为资料缺失。
   - 计划项没有自带日期、自身摘录点名了绝对日期时：该项的检索日期取摘录里的日期（`_item_dates`），不再用整轮第一个日期；随后按上面的规则绑定。
   - `static_fact` 项只要有一个小句未绑定，就不再用整项问法取证：已绑定的小句各自按「小句原文 + 绑定日期」取证，未绑定的小句回未确认（复用 stay_query 剩余小句已有的逐小句取证路径，不新增分项规划）。
   - 正常出口、协议失败回退（`availability_fallback`）、日期澄清共用这一处判定；同轮已核验条目的跨项复用也按接收项的绑定日期核验有效期。
3. **取证用剩余语义（R4）**：带工具锚点的小句，静态取证改用删除锚点后的剩余内容（`needs.residue`）作为问法；原小句仍用于范围核对与缺口编号，排除词仍按整轮原文。范围核对在剩余处理之前。
   - 对照：「早餐是否免费」「含早餐吗」仍要求收费/包含依据；已有资料的子问不产生转交候选。

### 2.4 R6：管理员状态转移用条件更新（`routes/knowledge.py` 的 `KnowledgeAdminService`）

- `convert_referral`：内容与范围校验通过后，用 `UPDATE … WHERE status = 已整理 AND generation = 页面代次` 原子取得入库资格，影响行数为 0 就拒绝（「草稿已变化…请刷新」），整个事务回滚、不建知识；成功后同一事务建知识、写知识编号与审计。PostgreSQL 行锁保留。
- 同类读后写一并改为条件更新：
  - `start_referral_draft`：`WHERE status ∈ 可整理状态 AND generation = 读到的代次`，同时换代、清草稿、写冻结编号，目标状态为「冻结列表非空 → 整理中，否则 → 没找到答案」（v2，F3-S4，保留现有空来源契约）；只有取得资格且冻结列表非空才按**新代次**入队一次；状态、作业、审计同一事务，失败全部回滚；
  - `close_referral`：`WHERE status ∈ 开放状态`。
- 沿用仓储 `finish_draft` 已有的条件写回写法，不新增锁服务。

### 2.5 R7：资料核实列表分页（`list_recent`、`referral_index`、`referrals.html`）

- 排序：开放状态在前，其余按创建时间倒序，同时间按编号倒序（稳定）。
- 分页：每页 50 条，`page` 参数（1–10000），上一页/下一页链接，与知识列表同一模式；每页查询量有限，不改成无限加载。
- 待处理数量的统计口径不变（开放状态全部），`count_open` 改为数据库 COUNT，不再读出全部编号计数。
- 直接牵连：分页偏移须穿过 `application.SessionKnowledgeAdminService.list_referrals`，否则实际装配的后台路由不能翻页；只补已有适配器的参数转发。

### 2.6 R8：启用拒绝回到原页面（`toggle_knowledge`）

- 捕获 `KnowledgeFormError`，把经 `safe_return_path` 校验、以知识列表为兜底的来源地址挂到异常的 `return_to` 上，再交给全局处理器；保留筛选与锚点。
- 接口请求仍返回 422；停用不校验；CSRF 仍只消费一次。

## 3. 第三段：风险、验证与决策

### 3.1 风险

- R1 漏识别风险：英文「is」写法要求值含数字或符号，纯字母密码（`password is sunshine`）不识别，会进入客诉模型输入、草稿或知识（D-H3 已接受的上限，写进 ponytail）。误遮：冒号写法会把「password: required」这类说明也当凭据遮掉，只影响可读性。
- R3：小句问的日期在该项检索范围外（如住一晚、问退房日早餐）回未确认；在范围内的另一天（住两晚、问第二天早餐）按那一天取证，查不到才记资料缺失。这是 fix2 Spec 已承诺的取舍。
- R4：剩余语义里可能带连接词（「和早餐几点开始」），主题与属性识别不受影响；若剩余为空则该小句本来就不做静态取证。
- R3/R4/R5 改变主回复共享判定，rc-1.70.0-3 的门禁结论失效，需要重新跑全量真实模型门禁。
- 本轮为分页补 `application.py` 既有会话适配器的偏移参数转发，按项目装配门禁跑本地全量。
