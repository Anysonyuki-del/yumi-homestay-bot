# 1.70.4 句内房号省略追问承接 Spec（v4.1，待用户确认与开始）

**目标**：同一行里，静态问题后面紧跟一个只换了房号的省略追问（例如「401早餐几点，302呢」「明天401早餐几点，那302呢」）时，无论规划怎么拆项、标成什么类型、有没有日期，结果都要确定、可验证：

- 结构匹配并且绑定成功（§2.0 的 B、C 类）：按工具承接或静态承接作答。静态承接用「父问题的规范问法 + 追问自己的房间 + 父问题已证明的日期和条件」单独取证。
- 结构匹配但绑定失败（D 类）：保守回未确认，不转交，不追问入住日期，也不用其他房间的资料顶替。
- 结构不匹配（A 类）：完全沿用现有流程，本 Spec 不改变。

- 起因：Codex《1.70.1–1.70.3 总交接审查》重点问题一；用户 2026-10-17 回复「开」。
- v2 依据：[Codex Spec v1 审查](../reviews/2026-10-17_codex-to-claude-room-follow-up-topic-spec-review.md)。T-R1 至 T-R5、C1、C2 逐条回应见 §4。
- v4.1：按 [Codex v4 复审](../reviews/2026-10-17_codex-to-claude-room-follow-up-topic-spec-v4-review.md) C4-1（P3）澄清 §2.0 的入口措辞；复审结论为没有新的 P1、P2 阻断项。
- v4 依据：[Codex Spec v3 复审](../reviews/2026-10-17_codex-to-claude-room-follow-up-topic-spec-v3-review.md)。V3-R1、V3-R2 见 §2.0、§2.1、§2.5、§2.7、§4。
- v3 依据：[Codex Spec v2 复审](../reviews/2026-10-17_codex-to-claude-room-follow-up-topic-spec-v2-review.md)。V2-R1 至 V2-R3 和两处补充见 §2.0、§2.1、§2.4、§2.7、§4。

## 1. 第一段：现状证据

### 1.1 「401早餐几点，302呢」在不同规划下的当前结果

401、302 各有一条专属早餐条目（8:00、9:00）。

| 编号 | 规划（都能通过 `verify_turn_plan`） | 当前结果 |
| --- | --- | --- |
| P1 | 两项 static_fact，第二项 `question` 补全为「302早餐几点开始？」 | 两间都答对 |
| P2 | 两项 static_fact，第二项 `question` 为空，回落为「302呢」 | 302 回通用未确认，缺口为 **knowledge_missing，可转交** |
| P3 | 一项 static_fact，`target_room=401` | 401 正确；302 为 scope_unbound |
| P4 | 一项 static_fact，不填房号 | 401、302 都是 scope_unbound |
| P5 | 一项 stay_query（误标），`target_room=401` | 401 正确；302 追问入住日期 |
| P6（T-R1） | 「明天401早餐几点，302呢」，一项 stay_query，带规划日期 | 401 正确；302 为 tool_uncovered，「这次没有查到对应的房态」 |

### 1.2 根因与约束

- 省略追问本身没有话题，话题在同一行前面的小句里，目前没有确定性的承接。
- `clause_residue` 为空只说明「没有别的待答资料」，不能证明是省略追问：「我想订302」「我想住302」「我要302」「302呢」四种写法的残留都为空，也都没有工具锚点（T-R2）。
- `_item_dates` 只从规划日期或 `quote` 取日期，不读 `question`；只补问法会按今天去查，日期错（T-R3）。
- 检索、模型证据选择、调用前缺口选项、最终缺口编号和转交都按**项**组织；`verify_selected_evidence` 不会按问句里的房号再核一次房源。只扩大同一项的候选池，会放行错房答案（T-R4）。
- `verify_turn_plan` 允许摘录重叠：整句一项，再加一项「302呢」，两项都有效（T-R4）。
- `MessageService.collect_guest_batch` 用换行合并多条消息，适配器分不清「同一条消息里的换行」和「两条消息的边界」（C1）。

## 2. 第二段：方案

在现有共享小句布局 `_ItemLayout` 上补一个「最终单元」概念，一次冻结信任边界。正常出口、协议回退、跨项复用、调用前缺口选项、工具覆盖和最终转交都读它。不新增模型调用、规划器或意图模型。

### 2.0 两步判定与分流表（V2-R1、V3-R1）

适用对象：每个没有工具锚点、点名了房号的小句（或计划项摘录），都**先**按 §2.1 做结构识别。判定分两步，每个对象只得到一个结果。

入口不以 `clause_needs(...).residue` 为空作前置条件（C4-1）：「302也是吗」「302也一样吗」「302也这样吗」的剩余分别是「也是」「也一样」「也样」，但都属于省略句式；而「我想订302」虽然剩余为空，结构不匹配，仍是 A 类。也不为此扩充 `clause_residue` 的删除词表，以免影响其他调用方。

**第一步：结构匹配（§2.1）。** 只看原文结构：没有日期，并且完整匹配省略句式。不匹配的就是 A 类，判定到此结束。

**第二步：绑定。** 结构匹配后，按顺序判断，第一条命中的就是结果：

1. 同一行里紧挨着的前一个单元是工具问法（房态、参考价、目录）→ **B 类**。追问的房号是否能解析，交给工具覆盖按现有安全契约处理。
2. 同一行里紧挨着的前一个单元是静态问题，追问房号状态为 resolved，父单元的日期能绑定 → **C 类**。
3. 其余情况都是 **D 类**，包括：
   - 没有前一个单元；
   - 和前一个单元之间隔着换行；
   - 父单元是动作请求或订房请求；
   - 父单元的日期无法绑定；
   - 追问房号为 unknown、ambiguous 或 unavailable（房源资料读取失败）。

| 类别 | 处理 |
| --- | --- |
| A 结构不匹配（「我想订302」「我想住302」「我要302」「302」，以及带日期的「10月10日302呢」） | **完全沿用现有流程**：住宿、目录项里是工具目标，可以照常开放工具、追问日期；静态项里按现有规则处理。本 Spec 不改变它 |
| B 工具承接 | 工具目标，沿用 1.70.3 的覆盖逻辑（R172-1 不回退） |
| C 静态承接 | 按 §2.3 至 §2.5 独立取证作答；属于纯静态单元，不开放、不展示工具结果（§2.7） |
| D 结构匹配但绑定失败 | scope_unbound，不可转交，不追问入住日期，不开放、不展示工具结果 |

「不追问入住日期」只适用于 C、D 两类。

### 2.1 第一步：省略句式的结构匹配（T-R2、V2-R2）

只核原文结构，不涉及房号能否解析、有没有父句、是否同一行。这几项都放在第二步。

1. **先检查日期**：小句里只要出现日期写法（绝对日期、相对日期、无锚点序数日，或者能识别但无法绑定的日期），就不匹配，归 A 类。日期信号不能被删掉。
2. 只去掉空白和外层标点，再完整匹配以下句式之一（`302` 代表任意房号写法，包括带楼栋、「房间」后缀的写法）：
   - 「302呢」「那302呢」「那么302呢」
   - 「302的呢」
   - 「302也是吗」「302也一样吗」「302也这样吗」

这是一组有限、明确的省略句式，不是订房动词排除表。「我想订302」「我要302」「401早餐几点，302」里不带「呢」的部分都不匹配。

### 2.2 父问题：原文相邻、同一行、只往前一个单元（C1）

- 边界：在本轮冻结的正文里，按原文位置排序（不按模型给出的数组顺序），只看**同一行内紧挨着的前一个单元**。遇到换行就断开，所以同一条消息里跨行的承接本版不支持，作为已知上限。
- 父单元必须是静态问题：本身有静态剩余内容，或者本身就是已经规范化的省略追问。连续追问（「401早餐几点，302呢，501呢」）时，501 承接 302 已经规范化的问法。
- 父单元是工具问法（如「明天401还有房吗，302呢」）时，追问是工具目标，沿用 1.70.3 的覆盖逻辑。这条优先级保证 R172-1 不回退。
- 父单元是动作请求、订房请求、新话题，或本身证明不了时，不往更早的单元回找，追问判为无法继承（§2.5）。

### 2.3 冻结的单元内容（T-R1、T-R3）

| 字段 | 来源 |
| --- | --- |
| 规范问法 | 父单元的规范问法（父单元所在项的 `question`；拆过的小句用小句剩余内容）去掉房号写法后，再接上追问自己的房号写法，例如「302早餐几点开始？」 |
| 房源 | 追问自己解析出的房源 |
| 日期 | 继承父单元已证明的 `static_dates`；父单元日期无法绑定时，追问归 D 类。追问自己写了日期的，按 §2.1 第 1 条不进入本功能，所以不存在「借父日期覆盖子日期」的情况。不扩大住宿区间，也不从父答案或模型补写的内容推日期 |
| 条件 | 附加条件词只取父单元已绑定的原文区间（作为检索的 `trigger_text`）；排除词仍核本轮全文。不借另一个独立问题的条件 |
| 缺口编号 | 追问自己的原文区间，用 `unit_id_for`，与调用前、调用后保持一致 |

日期不作为住宿意图的证明（T-R1）。「明天401早餐几点，302呢」里，父单元是静态早餐问题，所以 302 按明天的早餐资料作答，不管这一项被标成 stay_query，也不管有没有规划日期。

### 2.4 逐单元取证与候选隔离（T-R4）

- 一项里的静态单元解析出多个房源（P3、P4），或者包含省略追问时，按单元检索：每个单元用自己的房源、日期、规范问法和条件检索，得到自己的合法候选。
- 模型的项级证据选择用到某个单元时，先与该单元的合法候选取交集；交集为空时，按现有协议回退，走按对象约束的本地证据计划。不能直接信任同一项里其他房源的选择。
- 摘录重叠时，先按原文小句区间确定唯一的单元，再确定计划项归属，规则依次为：起点更早；起点相同时，覆盖更短的项；仍相同时，计划项 id 更小。归属与模型给出的数组顺序无关。父话题取原文相邻的单元，不取被重叠项整体吞掉的、含多个话题的整项问法。
- 预算：新增的单元检索计入现有的 `_PLAN_RETRIEVAL_ITEMS=4` 和 `_PLAN_KNOWLEDGE_TOTAL_CHARS=18000` 总量，不变成「每个小句四次」。超出预算的单元记 budget 原因，不可转交。
- `_gap_unit_offers`、`_item_evidence_plan`、`_shared_grounded`、`_tool_coverage`、`_referral_candidates`，以及 §2.7 的工具开放与组合，都读同一份单元身份。

### 2.5 失败与转交（T-R5）

- **只继承问题，不继承父答案或候选。** 父句缺资料、冲突、需要复核、期间否决或超预算，都不影响追问的话题；追问用自己的房源独立取证。父单元的规范问法在布局阶段（调用前）就确定，不依赖父句最终能否作答，所以不会出现动态编号或正常、回退出口不一致。
- **成功继承后，追问的房源真缺资料**：按现有核实流程，可记 knowledge_missing 转交，与客人完整问一句「302早餐几点开始」一样（D-T5）。GapUnit 文本用规范问法，并带上继承来的日期和必要条件，日期沿用现有的分段日期写法，例如「2026-10-08：302早餐几点开始？」，不用「302呢」。管家卡片显示的就是这段文本（`conversation_service._refer_gaps` 保存 `unit.text`，没有独立的日期字段）。
- **D 类**（结构匹配但绑定失败，见 §2.0 第二步第 3 条）：记 scope_unbound，不可转交，不追问入住日期。模型主动选中这个编号，也不能升级成转交候选。A 类（结构不匹配）不归本条，沿用现有流程。
- **超预算**：记 budget，不可转交。

### 2.6 门禁与回归（C2）

- 新门禁场景 K-房号追问：「7701早餐几点开始？7702呢」。夹具新增两个虚构房源 7701、7702，各自带一条专属早餐资料。
  - 判据：两组「房号＋对应答案」整句匹配；场景内禁止出现互换后的答案；两间都要答到。
  - 先进 known_failures，限定三次全过后晋升，再跑 all。
- 离线回归：
  - P1 至 P6，每种都覆盖正常与回退出口；
  - 「明天401还有房吗，302呢」，工具路径不回退；
  - 「401早餐几点，我想订302 / 我想住302 / 我要302」，不被吞成早餐问题；
  - 两组不同日期同时出现：「10月8日401早餐几点，302呢；10月10日401早餐几点，501呢」，各自按本组日期检索；
  - 父句带附加条件、另一个独立问题带条件、全文有排除词；
  - 同一项里两个房源的答案相反，再故意让模型选错房源的条目；
  - 摘录重叠、连续追问、跨行（不承接）、超预算；
  - 父句和追问各自有无资料的四种组合，加上父句冲突、复核、期间否决、超预算；
  - 继承成功和继承失败两种情况下，模型都主动选中缺口编号，核对最终转交候选；
  - A 类对照（V2-R1）：「我想订302」「我想住302」「我要302」分别单独出现、接在早餐问题后，仍走既有住宿流程，核对工具调用、日期追问和静态结果；再与「302呢」无父句、父句是动作、父句是房态三种情况成对断言；
  - 日期对照（V2-R2）：父子同日、不同日、相对日、无锚点序数日、非法日期；302 在不同日期政策相反，不能借父日期确认子句；房态父句后的带日期片段保留现有区间端点规则；
  - 工具消费对照（V2-R3）：P5、P6 注入主模型主动调用房态或目录，正常与工具后协议回退两个出口的最终正文都只有静态答案或静态缺口；混合句「明天401还有房吗，302早餐几点，501呢」保留 401 的房态，302、501 只答早餐；
  - 重叠归属：起点相同、覆盖长度不同的计划项，调换数组顺序后，结果、有效日期和候选资格不变；
  - 转交卡片：继承成功、真缺资料时，最终保存的问法带日期和必要条件；
  - 入口（C4-1）：「302也是吗」「302也一样吗」「302也这样吗」与「302呢」得到相同的话题和房源绑定，并与真实订房请求成对对照；
  - 分流唯一性（V3-R1）：「401早餐几点，999呢」（D）、单独的「302呢」（D）、「401早餐几点」换行后接「302呢」（D）、「401早餐几点，我想订302」（A）、同号异栋（D）、房源资料读取失败（D）、父句是动作或订房（D）、父句是房态（B）。每种只有一个预期结果，分别覆盖 static_fact、stay_query、catalog_query 三种规划写法和正常、回退两个出口，核对缺口原因、是否追问日期、是否生成转交候选；
  - 工具目标三态（V3-R2）：「明天还有房吗，302早餐几点，401呢」全店房态不漏、302 和 401 只答早餐；「有什么房型」之后接静态追问；只有静态追问、模型硬调用工具；点名目标只返回了其他房源；有真实工具需求但结果为空。正常与工具后回退两个出口都核对最终正文和证据。

### 2.7 工具开放、结果筛选与组合（V2-R3）

单元职责要贯通到所有工具消费方，不只是覆盖判定：

- **工具开放（`_plan_tool_names`）**：一个计划项里所有单元都是 C 类，或者是其他纯静态单元时，即使这一项被标成 stay_query 或 catalog_query，也**不开放**房态、参考价、目录工具。只要还有 A、B 类单元，或有带工具锚点的小句，就照常开放。
- **工具目标的三种状态（V3-R2）**：工具目标不能只用一个房源集合表达。复用现有的房源解析状态，区分：
  1. **没有工具需求**：没有任何需要工具的单元（A、B 类，或带工具锚点的小句）。不开放工具；主模型硬调用时，结果不展示、不算覆盖。空集合绝不当作「全店」。
  2. **全店目标**：有真实工具需求，但需要工具的单元都没点名房间（例如「明天还有房吗」「有什么房型」）。保留现有的全店或上下文目标语义；C、D 类单元点名的房间不会把它收窄。
  3. **点名目标**：需要工具的单元点了房间。只用这些房源筛选；筛选为空也不扩大到其他房间；unknown、ambiguous、unavailable 按现有安全契约处理（「没有找到」「暂时无法核对」）。

  全店目标和点名目标同时出现时，各自展示实际支持的结果并去重。覆盖仍按单元逐个核对房源、日期和事实类型。
- **结果筛选（`_tool_reply_parts`）**：按上面三种状态给出的目标筛选，不再用整轮的全部房号；C、D 类单元的房源不参与。
- **组合（`_compose_items`）**：如果主模型越过开放限制、仍调用了工具，或在协议回退后给出工具结果，只展示与需要工具的单元对应的工具分项；不对应任何需要工具的单元的工具分项丢弃，也不算覆盖。周末两种住法的组合同样遵守。
- 工具返回成功本身不能证明客人问的事实已被覆盖，是否覆盖仍由 `_tool_coverage` 按单元判定。

## 3. 第三段：风险、文件与决策

### 3.1 风险与上限

- 话题继承只看紧挨着的前一个单元。客人中途换话题时（「401早餐几点，停车怎么收费，302呢」），302 继承「停车」，这符合省略句的一般理解。
- 跨行承接不支持。省略句式之外的写法（「302」「302怎么样」）也不承接，保守处理。
- 按单元检索会多花检索预算，只在一项里有多个房源或有省略追问时才发生，并且计入现有总预算。

## 8. 门禁场景话题调整（2026-10-17）

§2.6 原定的 K-房号追问用早餐，即「7701早餐几点开始？7702呢」。候选 rc-1.70.4-1 的限定门禁首轮未通过。容器里只读诊断（虚构资料、真实规划与主模型）显示：

- 规划是标准拆分，7702 正确冻结为 C 单元；
- 但模型把全店早餐资料 9011（7:30 至 9:30）标为相关。它与房间专属的 8:15、9:45 在钟点上矛盾，按 1.70.0 起的既有冲突规则，两间都回未确认。

这是夹具设计问题，资料本身互相矛盾，与承接无关。场景改为不含钟点和价格的卫浴话题「7701有浴缸吗？7702呢」，与 K-带栋房号 同一模式。候选 rc-1.70.4-2 限定门禁三次全过，已晋升 must_pass。

另记观察项：「房间专属资料与全店通用资料在钟点上不一致时，是否让专属资料优先」属于知识取证规则，本版不改。
