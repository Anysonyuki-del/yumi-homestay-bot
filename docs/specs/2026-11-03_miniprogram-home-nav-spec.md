# 小程序首页快捷导航与布局重排 Spec

状态：待用户审阅。用户回复「开始」前不写代码。

范围来源（用户 2026-11-03）：
- 用户原话：「首页增加一个导航二级菜单，用 uiux 技能重新设计功能点和布局」。
- 这里把「导航二级菜单」理解为：首页上的一排快捷入口，每个入口通往一个二级页面或动作。它不是底部标签栏的第二层。理解有误请在 D1 指出。
- 本 Spec 在质感 Spec（`docs/specs/2026-11-03_miniprogram-texture-spec.md`，分支 `feat/miniprogram-texture`，未提交）的基础上继续。

ui-ux-pro-max 这次推荐的设计系统是深色、海军蓝配金色，与已定的暖色主题冲突，不采用。采用它的这几条准则：
- 触控区不小于 44×44px，相邻可点元素间隔不小于 8px；
- 关键功能 3–5 个；
- 主操作放在首屏和页面末尾；
- 固定悬浮元素不能遮住内容；
- 页内跳转用平滑滚动。

## 一、现状证据

- **首页结构**（`pages/home/index.wxml`，质感改版后），从上到下：
  1. 横幅轮播：没有横幅时不显示；
  2. 门店名和简介：没填时显示「YuMi 民宿」品牌开头；
  3. 「房间」标题；
  4. 满宽房间卡片；
  5. 右下角固定的「问管家」悬浮按钮（`.ask-host`，`app.wxss`）。
- **首页缺什么**
  - 客人打开小程序最常做的几件事：找到店、看入住须知（入住退房时间、Wi-Fi、停车）、联系管家。首页上只有「问管家」能直接点到。
  - 入住指南在「服务」标签里，地址和导航在「我的 → 关于本店」里，都要两步以上才能到。
  - 悬浮按钮压在房间卡片上。房间卡片改成满宽大图后，遮挡更明显。
- **数据来源**
  - 首页已经读取 `/api/miniprogram/home`（`utils/content.js::fetchHome`），门店的 `address`、`location`（经纬度）、`phone` 都已拿到。
  - 新入口不需要额外的请求，也不需要改后端。
- **可复用的现有实现**
  - 地图导航在 `pages/me/about.js::openMap`：用 `wx.openLocation`，没有坐标时不打开，失败时提示「暂时无法打开地图」。
  - 联系管家：`utils/service-chat.js::openServiceChat`。在线客服没开通时，会退回拨打门店电话。
  - 服务页是底部标签页，路径 `/pages/services/index`，只能用 `wx.switchTab` 打开。

## 二、功能点

### N1 快捷导航（首页的二级菜单）

- **位置**：放在门店名和简介下方、「房间」标题上方，首屏就能看到。
- **样式**
  - 一张暖奶油底的卡片，圆角 24rpx，一行四格均分。
  - 每格：88rpx 圆形浅底，里面是 44rpx 珊瑚深色线条图标；下面是 24rpx 标签。
  - 每格的可点区域约 86×75px，大于 44px 的触控下限。
  - 按下时该格变淡，不缩小。
- **四个入口**（D1 选 a）：

| 入口 | 图标 | 点击后 |
|---|---|---|
| 到店导航 | `location` | 门店填了坐标：直接打开微信地图导航，带上店名和地址。没填坐标：进入「关于本店」页，那里能看到并复制地址 |
| 入住指南 | `book` | 切到「服务」标签 |
| 联系管家 | `chat` | 和其他「问管家」入口一样：在线客服开通时打开客服，没开通时退回拨打门店电话 |
| 关于本店 | `shop` | 进入「关于本店」页 |

- **显示条件**：加载完成后（有房间或没有房间都算）显示；加载中和出错时不显示。
- **复用地图逻辑**：「到店导航」和关于页的 `openMap` 是同一件事。把这段逻辑抽成 `utils/store-map.js::openStoreMap(store)`，两处共用。

### N2 首页布局重排

新的顺序：
1. 横幅（不变）；
2. 门店名和简介，或品牌开头（不变）；
3. N1 快捷导航（新增）；
4. 「房间」标题，右侧加一行小字「共 N 间」（只在有房间时显示）；
5. 房间大图卡片（不变）；
6. 页尾「联系管家」条（新增），样式与服务页的「联系管家」条相同，文字为「还有问题？直接问管家」；
7. 去掉首页的「问管家」悬浮按钮（D2）。快捷导航和页尾两处已经提供这个入口，悬浮按钮不再遮挡房间卡片。

房间为空时，「房间」下方仍显示紧凑空状态，它自带「问管家」按钮。此时页尾的「联系管家」条也隐藏，避免同一屏出现两个相同按钮。

### N3 测试（只写有判别力的）

小程序 Node 测试：
- **`openStoreMap`**
  - 有坐标时调用 `openLocation`，带上经纬度、店名和地址；
  - 没有坐标时进入关于页，不调用 `openLocation`；
  - `store` 为 null 时同样进入关于页。
- **首页快捷导航**
  - 「入住指南」调用 `switchTab('/pages/services/index')`；
  - 「关于本店」进入关于页；
  - 「联系管家」走客服兜底，客服未开通、有电话时弹出拨打确认框。
- **关于页**：改用 `openStoreMap` 后，原有的「没坐标不打开地图」测试继续通过。
- **首页房间数**：页面数据里的房间数等于实际房间数。

样式和布局不写测试，靠开发者工具预览验收。新测试做变异检查。

## 三、风险与决策

- **D1 入口内容**（建议 a）
  - (a) 四个固定入口：到店导航、入住指南、联系管家、关于本店。每个入口都永远能用，布局稳定，不需要额外请求。
  - (b) 到店导航、联系管家，再加入住指南里排在前面的两个分类（比如 Wi-Fi、停车）直达分类页。更贴近客人的高频问题，但代价是：
    - 首页要多读一次 `/guide`；
    - 入口会随后台知识的勾选变化；
    - 分类名长短不一，四格会参差不齐。
  - 选 (a) 的理由：服务页已经按分类展示，入住指南入口一步就能到；首页优先保证稳定和不出错。
- **D2 去掉首页悬浮按钮**（建议去掉）
  - 理由：快捷导航和页尾都有联系管家；满宽大图卡片被悬浮按钮遮挡；技能准则要求固定元素不遮挡内容。
  - 只去首页的。分类页的悬浮按钮和详情页的底栏保留：那两页没有别的联系入口。
  - 代价：滚到页面中间时，要回到顶部或拉到底部才能联系管家。
- **D3 门店信息为空时「到店导航」也显示**
  - 点了进入关于页，关于页的空状态会提示「地址、交通和联系方式，可以先问管家」。
  - 这样四格布局固定，不会因为后台没填资料变成三格。
  - 前提：后台尽快填门店信息。线上现在门店信息是空的，填好后这个入口才真正有用。
- **D4 不新增依赖、不改后端、不加后台配置项**
  - 入口固定写在小程序里，不做后台可配置的入口（目前没有这个需求）。
- **风险**
  - `wx.openLocation` 需要真机验证。开发者工具里地图的表现和真机不同。
  - 首页去掉悬浮按钮后，客人可能更难找到联系入口。需要你预览后确认，不合适就恢复悬浮按钮，只保留快捷导航。
- **不做**
  - 后台可配置的入口、入口角标。
  - 预订入口（价格和房态只认百居易，小程序不做预订）。
  - 天气、周边推荐这类需要外部接口的卡片。
- **验证与发布**
  - 只跑 `tests/miniprogram` 的 Node 测试，做变异检查，再做 WXML、JS 语法自查。不改后端，不跑后端测试。
  - 与质感改版、5MB 图片上限一起，作为 1.73.1 发布：更新 CHANGELOG，写 `docs/releases/1.73.1.md`。
  - 5MB 上限是后端改动，需要部署服务器；小程序由你「构建 npm」、上传、真机验收。
- **实施顺序**
  1. 抽出 `openStoreMap`，关于页改用它，补测试。
  2. 首页快捷导航和事件处理，补测试。
  3. 首页布局：「共 N 间」、页尾联系管家条、去掉悬浮按钮。
  4. 预览核对清单，并在本 Spec 追加实施记录。

## 四、实施记录（2026-11-03，用户「开始」）

N1–N3 本地实现完成，分支 `feat/miniprogram-texture`。没有提交，没有改版本号，也没有调用真实微信接口。上面「状态：待用户审阅」是写 Spec 时的状态。D1 选 (a) 四个固定入口，D2 去掉首页悬浮按钮。

- **改动**
  - **新增 `utils/store-map.js::openStoreMap`**
    - 有坐标：打开微信地图，带上店名和地址。
    - 没有坐标或没有门店信息：进入关于页。
    - 关于页 `openMap` 改用这个函数。
  - **首页**（`pages/home/index.*`）
    - 门店名下方新增快捷导航，入口定义在 `QUICK_NAV`，点击由 `openQuickNav` 处理。
    - 「房间」标题右侧显示「共 N 间」。
    - 页尾新增「还有问题？直接问管家」条。
    - 去掉悬浮按钮；页面底部留白从 200rpx 减到 64rpx。
- **与 Spec 的偏差和补充**
  - `openStoreMap` 增加参数 `fromAbout`：已经在关于页时，没有坐标就什么都不做，避免再打开一个关于页。关于页的行为与改动前一致。
  - 「共 N 间」直接在页面模板里用 `rooms.length` 显示，没有另存页面数据，因此没写单独的测试。
  - 首页页尾条的说明文字是「房型、入住安排都可以问。」。
- **验证**
  - 小程序 Node 测试 41 项通过。新增：
    - 到店导航：有坐标、没坐标、门店为空、在关于页四种情况；
    - 首页快捷导航：入口顺序，以及四个入口各自的去向，联系管家走客服兜底拨号。
  - 关于页测试补了一条断言：没坐标时不会再打开关于页。
  - 变异检查 8 处全部被测试抓到。第一次检查发现关于页这条断言缺失，补上后才抓到。
  - 首页 WXML 结构、JS 语法、页面 JSON 自查通过。
- **预览核对清单**

  4. 「房间」标题右侧显示「共 N 间」。
