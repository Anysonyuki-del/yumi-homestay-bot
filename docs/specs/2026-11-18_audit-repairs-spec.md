# 2026-11-18 审计修复

依据上一轮审计的七项复现与修复建议，用户指示「按你的理解来修复」。在本地工作区实施，既有部署的数据库密码轮换另行安排。

| 范围 | 现状与实施决定 | 验收 |
|---|---|---|
| 本机启动与备份 | `deploy/start.sh` 从完整运行配置取启动参数，且仅复制 SQLite 主文件。改用 `BootstrapSettings`，迁移前用 SQLite 在线备份保留已提交 WAL；备份或版本检查失败即中止。沿用私有附件备份。 | 只有基础配置时运行启动准备；恢复备份可以读到未检查点的已提交行。 |
| 迁移连接串 | `migrations/env.py` 把 URL 直接交给配置插值。保持驱动收到原始 URL，避免百分号引起插值异常及凭据回显。 | 含百分号编码密码的合成 PostgreSQL URL 可迁移，输出不含凭据。 |
| Compose 数据库 | `compose.yaml` 为新卷设置固定口令。改为必填变量，并说明原始密码与数据库 URL 编码规则；旧卷依旧使用已有角色密码。 | 填入合成值后配置有效；缺失或空值明确报错；旧卷切换说明可操作。 |
| 出站图片 | `SQLAlchemyJobRepository.recover_stale` 会把中断的发送重新排队。已明确安全的失败沿用现有重试；发送结果未知则终止自动重发和续链，事务内登记一次员工核查，表述准确。 | 对过期作业反复恢复，图片不可再领取，核查只生成一次；普通图片发送与安全重试可用。 |
| worker 空转 | `application._run_worker_loop` 每轮领取均扫描遗留作业。每个分片启动即扫描，随后按单调时钟每 30 秒恢复一次，提交失败不延后重试。 | 两次成功恢复之间持续正常领取，空闲不逐秒扫描；五分钟过期线与分片隔离保持。 |
| CRM | `SQLAlchemyCustomerRepository.list_customers/customer_list_facts` 只过滤 cancelled。两个入口共用领域的排除状态集合，识别已有数据的大小写和首尾空白。 | 被排除订单在列表与筛选一致；正常订单仍可展示。 |

Alembic 的本机默认目标保留主机、角色和库名，移除与旧 Compose 重复的固定口令。配置文件明确采用操作系统路径分隔符，单个项目根目录的导入行为一致。

使用本地临时 SQLite、独立 PostgreSQL 和模拟外部响应。修改应用装配后执行离线全量。对审计中已定位的 SQLite 测试连接泄漏，通过测试夹具在事件循环关闭前归还连接并释放引擎。保留上一轮五项工作区修改，索引在改动稳定后统一维护。
