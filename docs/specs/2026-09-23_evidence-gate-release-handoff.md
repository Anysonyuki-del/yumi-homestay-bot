# 交接报告：知识证据门属性校验与 1.39.0 发布

日期：2026-09-23。本文是接手入口。

## 1. 一句话现状

证据门改造已实施、验证并发布到 `main`（标签 `v1.39.0`，CI 通过）；**生产尚未部署**。语义检索代码仍默认关闭，生产知识库仍为 0 条。

## 2. 本轮解决的问题

上一轮交接（`2026-09-22_claude-to-codex-evidence-gate-handoff.md`）只报告了一条错误放行。方案评审（Codex，`2026-09-22_knowledge-evidence-gate-spec.md`）指出评估脚本自己实现了一套放行判断，与真实回复链路不一致，因而掩盖了真实缺口。用真实 `respond` 链路复现确认，模型的错误事实会原样发给客人：

| 问题 | 审核知识 | 修复前的最终回复 |
| --- | --- | --- |
| 屋里闷热能自己调凉吗 | 空调 18～30℃ | 可以调到 10 摄氏度。 |
| When are quiet hours? | 22:00 至次日 08:00 | Quiet hours are from 6:00 p.m. to 6:00 a.m. |
| 早餐能做无麸质的吗 | 只有送达时间 | 可以提供无麸质早餐。 |
| 大床房今晚多少钱 | 无实时查询结果 | 今晚大床房 300 元。 |

前两条在知识库为空时同样会发出，因此**该缺口在 1.39.0 部署前的生产环境上一直存在**。

## 3. 改动

| 文件 | 内容 |
| --- | --- |
| `services/knowledge_evidence_policy.py`（新增） | 证据计划：问题拆成「主题 + 所问属性」，答案须覆盖每一项；最少完整答案；指令夹带、冲突答案、超长拼接一律保守处理 |
| `services/knowledge_service.py` | 主题清单补 13 项（温控、卫浴、安静时段、床品、洗护用品、儿童、客房清洁、用电、饮用水、代收、电视、消防安全、公共区域）；英文 check in/out 归入入住退房 |
| `integrations/deepseek_client.py` | 静态分支接管回复并跳过精炼；交易金额缺实时依据转员工确认；店外范围词表补「巷口」「路口」与「与本店无关」声明 |
| `tests/unit/test_knowledge_evidence_gate.py`（新增，21 条） | 验收矩阵 T01～T14 的真实出口断言 |
| `tests/unit/test_knowledge_retrieval_eval.py` | 放行口径改用生产的证据计划；模拟回复走真实 `respond`；新增第四套留出集登记 |
| `tests/fixtures/knowledge_retrieval_holdout_v4.json`（新增） | 第四套留出集，40 条 |

产品口径变化（用户已确认）：静态本店问答证据齐全时发审核答案原文，模型改写不参与事实；没有客人语言的答案时回未确认，不翻译；指代不清时同一话题最多反问一次。

## 6. 已知上限（不要当成已解决）

- 属性与主题都是**有限的人工清单**。清单外的具体对象仍可能被同主题的其它答案背书，这是结构性上限，不是再加几个词能消除的。
- 关键词检索对口语问法覆盖不足：`holdout_v4` 纯关键词 Recall@3 只有 0.611。语义检索能提到 0.944，但**尚未开启**。
- 证据门准确率普遍在 0.6～0.75，意味着不少本来有答案的问题仍回「尚未确认」。安全优先的代价。
- 六套评估集**全部**已用于修复，只能作回归。再声称泛化效果需要第五套。
- 真实聊天模型未验收（用户决定跳过）；真实生产延迟未测。
