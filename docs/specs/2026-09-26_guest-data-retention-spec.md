# 客人数据记录与保留放开 Spec（1.41.0）

版本：R1，2026-09-26。状态：**待用户确认；确认后等待「开始」再编码。**

基线：main `68417df`（1.40.1）。

## 1. 依据

用户原话：「取消所有的隐私防护，允许记录客人信息，只是不要传到github」。

我把现有防护分成四类让用户选，用户回复「开放1和3」：

| 类别 | 用户决定 |
| --- | --- |
| ① 服务器日志与排障记录 | 放开 |
| ② 发给 DeepSeek 前的脱敏 | 保留 |
| ③ 数据库加密与到期清除 | 放开：客人个人信息存明文，不再到期清除 |
| ④ 对客人的安全门（聊天不发门锁密码、未核实身份不展示订单、客人之间互不可见） | 保留 |

硬约束：客人数据不得进入 GitHub。

## 2. 已核实现状

以下路径均以 `src/homestay_bot/` 为前缀。

| 机制 | 现在的行为 | 依据 | 本次 |
| --- | --- | --- | --- |
| 日志脱敏过滤器 | 字段名带 mobile、phone 的值打码；token、password、api_key 等替换为 `[REDACTED]` | `logging.py::SensitiveDataFilter`、`_redact_value`、`_mask_mobile` | 手机号打码取消；**密钥类脱敏保留**（不是客人信息，泄露会导致服务器被入侵） |

| 客户手机号 | 只存密文，另存指纹用于查找；后台显示打码 | `domain/models.py::Customer.phone_ciphertext/phone_fingerprint`、`services/customer_service.py`、`services/customer_admin_service.py::_masked_phone` | 存明文；指纹保留用于查找；后台显示见确认点 2 |
| 门锁凭证与入住指引 | 加密存放（`room_password`、`checkin_guide`） | `repositories/credentials.py`、`services/credential_delivery.py` | **不变**：属于 ④ 房屋安全 |

## 3. 功能点

| 编号 | 内容 |
| --- | --- |
| G1 日志 | `SensitiveDataFilter` 不再对 mobile、phone 字段打码。密钥、令牌、密码、授权头、URL 查询参数里的凭据仍然替换为 `[REDACTED]` |
| G2 作业载荷 | 上述几类作业完成或失败后保留载荷，排障时能看到发了什么、会话编号是多少。1.39.16 验收时就因载荷被清空，无法在线上复核会话编号 |
| G3 对话正文 | 长摘要照常生成、供模型上下文使用，原文不再清空。模型上下文仍只取最近 7 天，这一点不变 |
| G4 预订审批 | 新增明文列 `guest_name`、`guest_mobile`、`special_requests`，写入时存明文，读取优先明文。停止到期清除。已有记录由一次性工具在生产容器内解密回填，与 `tools/import_knowledge_drafts.py` 同样模式：默认预览，`--apply` 才写库。旧密文列保留一个版本用于回滚，下一版再删 |
| G5 客户手机号 | 新增明文列 `phone`，写入时存明文，指纹保留用于查找；已有记录同样由一次性工具回填 |
| G6 不进 GitHub | 新增仓库守护测试：受跟踪的文件里不得出现真实形态的手机号、身份证号，虚构资料和测试用的号码走白名单；`.gitignore` 确认覆盖数据库文件、日志、备份与导出文件。CI 每次都跑 |

**不在本次范围**：② 发给模型前的脱敏；④ 对客人的安全门；门锁凭证加密；密钥类日志脱敏。

## 4. 已清除的数据无法恢复

- 已被清空的对话正文，以及已到期清除的审批个人信息（`pii_purged_at` 已设置），本次无法恢复。
- 本次只影响今后的数据，和尚未清除的存量。

## 6. 验证与发布

- **本地**：迁移在隔离的 SQLite 上做 upgrade、带数据 upgrade、downgrade、再 upgrade；另跑全量测试、Ruff、mypy。
- **部署**：走现有流程；部署前备份与可读性复验照常；改了 `services/` 与 `repositories/`，会触发回归门禁。
- **回填**：回填是生产写入，单独请你授权。先预览条数，再执行，执行前另做一次备份。

## 7. 风险

- **数据库和备份里存的是明文客人信息**。服务器或备份一旦泄露，会直接暴露姓名和手机号；备份文件在服务器的备份目录里。
- **合规**：客人个人信息长期明文保存、不设期限，在个人信息保护法上需要有合法依据和保存期限说明。这是经营决定，由你判断。
- **与边界补充 P12 冲突**：P12 原定核对信息「加密存放、14 天后清除」，按本次决定应改为明文、不清除。「不给模型看」「管家确认前不据此展示订单」属于 ② 和 ④，保留。修订写进给 Codex 的条目文件。
- **迁移与回滚**：旧密文列保留一个版本，回滚时应用可以回到读取密文；删除旧列放到下一版单独做。
