## 3. 功能点

### F1 共用虚构资料入库（Q17）

- 新增 `tests/fixtures/guest_reply_scenarios.json`，一个文件装下全部内容：
  - `_fictional`：虚构声明；
  - `today`：固定测试日；
  - `knowledge`：47 条；
  - `hostex`：房源、满房晚、备注、参考价；
  - `scenarios`：146 个；
  - `global_must_not_include`。
- **只扩充同义说法、不放宽禁令**：逐条复核 1.39.16 回归中人工判为「意思对、字面没过」的场景，只在必含片段里补同义说法，不删、不放宽任何禁用片段。
- **离线校验测试** `tests/unit/test_guest_reply_scenarios.py`，不调用模型：
  - 场景编号唯一；
  - `source_ids` 都能在知识里找到；
  - 期望路由在已知集合内；
  - 带虚构声明；
  - 全文不含手机号、身份证号、邮箱、链接格式的真实个人信息。
- **边界 Spec 扩展这个文件时的约定**：
  - 只追加场景、只给知识补字段；
  - 已有场景的编号和期望不改；
  - 确需修改期望，在基线文件里注明原因。

### F2 回归运行器入库

- 新增 `src/homestay_bot/tools/reply_regression.py`，把草稿区的运行与判定合并进来。它随候选源码一起上传，不依赖容器里已安装的旧版本。
  - **运行**：读取共用资料，逐个场景调用 `DeepSeekGuestAssistant.respond`。
    - 路由前的判定复用线上同一套：紧急、客诉、转人工、无关问题；
    - 回复出口复用 `prepare_guest_reply` 或 `prepare_facility_advice_reply`；
    - 百居易用按共用资料返回的替身，知识用内存仓储；
    - 不写库、不发消息、不访问百居易。
  - **配置**：只读解密当前运行配置，取 DeepSeek 地址、密钥和模型；密钥不离开容器，不写入任何输出。
  - **判定**：纯函数，按期望路由、必含片段、禁用片段逐条判定，离线单元测试覆盖。
  - **应对采样浮动**：每个场景先跑 1 次。不退步集合里的场景若失败，再补跑 2 次，3 次中失败至少 2 次才算退步；其他场景只跑 1 次。
  - **输出**：只含场景编号、路由、判定结果和客人可见正文（虚构内容），以及候选源码的版本与哈希，不含密钥和配置。
- **覆盖范围的上限写进工具说明**：它测回复决策链路，不测合并等待、出站队列、过时判定和企业微信投递，这些继续由集成测试和测试号收件兜底。

### F3 基线与「只进不退」（Q20）

- 新增 `tests/fixtures/guest_reply_regression_baseline.json`，包含：
  - `must_pass`：不退步集合；
  - `known_failures`：已知未通过的场景，每条写原因与类别，安全类单独标出；
  - `measured_on`：测量所用的版本、日期和运行次数。
- **首次基线**：用线上 1.39.16 把 146 个场景各跑 3 次。3 次全过的进 `must_pass`，其余进 `known_failures`。只把稳定通过的场景当作「已通过」，避免门禁被采样浮动误伤。
- **门禁判定**，以部署标签那个提交里的基线文件为准：
  - `must_pass` 里有任何一个场景按 F2 的规则算退步：不通过，中止部署；
  - 声明修复的场景，就是本次提交从 `known_failures` 移进 `must_pass` 的那些，同样要按规则通过；
  - `known_failures` 里新通过的场景：不挡发布，工具生成更新后的基线文件，发布后随现场记录提交，从此纳入不退步集合。这就是「修好后自动纳入」。
- **安全类已知缺陷**（紧急、提示注入、钱款）：每次发版由工具列出，写进发版记录。

### F4 部署接入（Q16）

- **新增入库脚本** `scripts/release/reply_gate.sh`，参数为标签。
  1. 判断本次是否改了回复链路：比较上一个版本标签与本标签之间的改动，只要涉及以下任一项就必须跑：
     - `src/homestay_bot/integrations/`；
     - `src/homestay_bot/services/`；
     - `src/homestay_bot/application.py`；
     - `tests/fixtures/guest_reply_*`；
     - `pyproject.toml` 里的依赖。

     没改则输出「本次未改回复链路，跳过」及文件清单。
  2. 用标签打出候选源码包，上传到服务器临时目录，复制进运行中的 API 容器，用 `PYTHONPATH` 加载候选源码运行 F2。
  3. 取回结果，按 F3 判定，退出码表示通过或不通过。
  4. 无论成败都清理服务器和容器里的临时目录（`trap`）。
  5. 结果写入 `.stage/reply-gate-<标签>.json` 和一份可直接贴进发版记录的中文摘要。
- **服务器地址与密钥**：由调用方通过环境变量传入，脚本不写死，不入库。
- **修改本机部署脚本** `run-deploy.command`（未跟踪、只在本机）：
  - 发布包自检之后、上传之前，调用门禁；不通过即中止，不上传、不部署。
  - 仓库路径改为可用环境变量 `DEPLOY_REPO` 覆盖。主工作目录有在途改动时，可以从独立 worktree 部署；1.39.16 是临时复制一份脚本做到的。
- **紧急修复时的跳过开关（确认点 1）**：支持 `--skip-reply-gate "<理由>"` 显式跳过，理由写入部署日志，发版记录必须写明。
- **DeepSeek 不可用时**：门禁无法运行，按不通过处理，不当作通过。

### F5 店外状态不推测（P14）

- **规则文字**：`fact_policy.FACT_SOURCE_RULE_ZH/EN` 补一句。

  > 会变化的店外状态（天气、气温、降雨、人流、排队、路况、营业或开放状态、活动安排）只能来自本轮的实时查询结果；没有查询结果就说暂时查不到，不按季节或经验推测。

  所有引用该常量的提示词自动生效，包括主回复、精炼、联网、改写重发和服务安抚，由架构测试守住。
- **确定性判定**：新增 `fact_policy.is_unsourced_external_state_claim(sentence)`。同时满足以下两条，且不是问句、建议或「查不到」这类说明时，判为推测：
  - 带时间指向，例如这几天、最近、近期、今天、今晚、明天、这周、现在；
  - 断言会变化的店外状态，例如偏凉、偏热、降温、下雨、晴、人多、排队、堵、开门、关门、营业、闭馆。

  例子：
  - 「这几天武汉早晚偏凉」：删；
  - 「建议出发前看一下天气预报」「明天的天气我这边暂时查不到」：留；
  - 「黄鹤楼在武昌区」「武汉夏天通常比较热」：留，不带时间指向，属于稳定常识。
- **接入位置**：非联网分支的模型回复一律过这道检查。
  - 位置：`deepseek_client.py::_validate_decision` 和精炼后的过滤处；
  - 不管有没有百居易工具作证、是不是本店专属问题都要查，因为 1.39.16 那句漏网，正是因为有房态工具作证而整段跳过了过滤；
  - 联网分支带着实时来源，不做这道检查。
- **删空时的兜底**：与 F6 用同一句中性说明（`guest_reply_policy.unconfirmed_fallback`）：「这项信息暂时无法确认。」，英文一版。（实施时统一为一处文本，与出口原有的空回复说明一致。）

### F6 删空后的无关兜底（1.39.16 回归发现，确认点 2）

`_remove_property_promotion` 整段删空时，改为中性说明，中英各一版：「这项信息暂时无法确认。」不再回退成「统一预算、分工查询」的行程建议。F5 和这里用同一处兜底文本。

## 6. 不在本版

- P9 至 P13 由边界 Spec 实施。
- 门禁只测回复决策链路，出站队列、过时判定和企业微信投递继续由集成测试和测试号收件兜底。
- 英文回复语言、约三成房态答复转人工、审核知识被判「尚未确认」等已知问题，不在本版修复，由基线列为已知缺陷。

## 7. 风险

- **采样浮动**：「3 次失败至少 2 次」仍有误报可能。误报时，重跑门禁是允许的；把不稳定场景移出 `must_pass` 必须在基线文件里写明原因，不能静默删除。
- **字面判定**：同义说法补得不全会造成误报；禁令只增不减，漏报风险不因本版增加。
- **成本与时间**：每次改回复链路的部署多出 15 至 25 分钟和几元费用。只改后台页面、文档等不涉及回复链路的部署自动跳过。
- **F5 的误删**：带时间指向的正常句子可能被删，例如客人自己说「明天下雨我们就不出门了」，机器人复述时。判定只作用于机器人回复中的断言句，并用反例测试守住。
- **合并**：共用资料文件是边界 Spec 规划的同名文件，本版先入库，那边合并 main 后在此基础上追加。`fact_policy`、`deepseek_client` 仍会与边界 Spec 的重构交叉，合并时由那边处理。

## 8. 确认点

1. **是否保留紧急修复时的跳过开关** `--skip-reply-gate "<理由>"`。推荐保留：DeepSeek 故障时安全补丁不该被卡住，理由会进部署日志和发版记录。
2. **F6 是否一起修**。推荐一起修：这和 F5 是同一个出口、同一处兜底文本，门禁也会量到。
