## 一、现状证据（改前）

- **A1 首页整页失败。** `pages/home/index.js::fetchHomePage` 用 `Promise.all([fetchHome(), fetchRooms()])` 等两个结果，任一失败整页进出错态，快捷导航也在成功分支里。旧测试明确要求「任一失败整页出错」。
- **A2 两页对同一份门店资料给出不同动作。**
  - 后台 `miniprogram_home_admin.py::_validated` 允许只填成对坐标。`miniprogram_content.py::MiniProgramContentService.home` 把坐标算作「已填」，返回非空门店。
  - 关于页 `about.wxml` 的位置行要求 `store.address` 存在才渲染，只有坐标时导航入口不显示。
  - 只填简介时，首页仍写「到店导航」（`utils/store-map.js::openStoreMap` 没有坐标就跳关于页），关于页却只有简介。
- **R3 房间图。**
  - 首页封面只有 `bindload` 能解除透明，封面地址失效时一直是空白暖底，也不出「照片整理中」。
  - 详情页无照片时仍留 600rpx 占位（`detail.wxss::.hero--empty`）。
- **R4 订单。** 「我的订单」行只弹 toast（`me/index.js::openOrders`），客人还得再找客服。登录是实心主按钮，但登录本期不解锁任何功能。
- **R6 服务卡片。** 分类名和首问预览都是单行截断（`services/index.wxss`）。

## 二、功能点

### A1 首页门店区与房间区分别加载

- `utils/content.js::loadPageData` 增加可选的 `{ statusKey, messageKey }`，代次按 `statusKey` 分开计数。`discardPendingLoads` 作废所有区块。其余页面不传参数，行为不变。
- 首页拆成 `loadHome`（`homeStatus` / `homeMessage`）和 `loadRooms`（`roomsStatus` / `roomsMessage`）。`load` 同时取两个区块，下拉刷新等两区都落定后才收起动画。
- 快捷导航从首屏起就渲染，不再等接口。
- **门店区失败**：仍以品牌名开头，一句说明加「重新加载」，只重取门店（`retryHome`）。到店动作退回 `unknown`，不沿用上一次的坐标。
- **房间区失败**：紧凑状态块加「重试」，只重取房间（`onStateAction`）。
- 两区都失败时，快捷导航的「联系管家」格仍是原生客服按钮。

### A2 到店动作两页同源

`utils/store-map.js::arrivalAction(store)` 返回 `map` / `copy` / `ask`。首页加载中或失败时为 `unknown`。

| 公开资料 | 首页快捷导航第一格 | 关于页位置行 |
|---|---|---|
| 有成对坐标（地址可空） | 「到店导航」→ 打开地图 | 「地址」+ 地址或「已在地图上标注门店位置」，动词「导航」 |
| 只有文字地址 | 「门店地址」→ 弹框显示完整地址，「复制地址」一次复制 | 地址 + 动词「复制」，点整行复制 |
| 坐标和地址都缺（即使有简介） | 「问怎么到店」，原生客服按钮 | 「到店路线 · 问管家怎么到店」，原生客服按钮 |
| 门店资料未取到 | 「到店导航」→ 进关于页（关于页自行加载与重试） | 关于页自身出错态 |

- 地图打不开时：有地址就弹框（标题「地图暂时打不开」）给出完整地址，由客人选「复制地址」或「关闭」，只在确认后写剪贴板；没有地址就提示「暂时无法打开地图」。（实施复审 F1：原先直接复制，会在客人没点「复制」时替换其剪贴板内容。）
- 复制失败时提示「复制没有成功，可在「关于本店」长按地址复制」。`wx.setClipboardData` 是微信隐私接口，隐私指引没声明「剪切板」时会走这条路。

### R3 无图或封面失效时用紧凑布局

- **首页**：有封面时保留 4:3 图位和淡入。`binderror` → `onCoverError` 置 `coverFailed`。封面事件带房间编号与封面地址，`markCover` 只回写仍对得上的那一项；列表刷新或换序后迟到的旧事件直接忽略（实施复审 F2）。没有封面或封面失效时去掉图位，改为浅底紧凑卡片，末尾一行「照片整理中」或「照片暂时没有加载出来」。
- **详情页**：无照片时不渲染图位，标题区下加「照片整理中，想看实拍可以问管家。」。加载中的 600rpx 占位保留。
- 详情页轮播项改为 `{ value, ariaLabel }`，读屏读出「房名，第 N 张，共 M 张，点按放大」；放大预览仍用 `room.photos` 地址列表。
- 详情页轮播里单张图片的加载失败本次不处理：t-swiper 不逐张暴露错误事件。

### R4 订单入口改为直接问管家

- 「我的订单 · 即将开放」改为原生客服按钮「向管家查订单」（`session-from="orders"`）。删除 `openOrders` 和 toast 文案。
- 「微信登录」由实心改为描边。
- 自助查单不在本期：展示订单前必须核实归属，不能按微信登录或客人自报手机号自动关联（三标签 Spec D1）。

### R6 服务卡片放宽截断

分类名与首问预览各放宽到两行。常用问题置顶需要真实客问数据和后台字段，本期不做。

## 三、风险与决策

- **D1 跳过分段确认**：用户本轮明确要求一次做完、中途不停。
- **D2 不升版本、不提交、不上传**：本次只改小程序客户端，服务器不用部署。提交、上传和真机验收等用户另行授权。
- **D3 复制地址依赖隐私指引**：上传前请在小程序后台「用户隐私保护指引」中声明「剪切板」。没有声明时，复制会失败并提示长按复制，不会无反应。
- **D4 首页快捷导航可能出现两个客服格**：门店既无坐标也无地址时，第一格「问怎么到店」和第三格「联系管家」都打开客服。保留两格的理由是前者说清了缺什么。后台补上地址或坐标后，第一格自动恢复。
- **暂缓**：R5 房间咨询卡片（理由见复核报告）、R6 常用问题置顶、自助查单。
- **未覆盖**：开发者工具与真机外观、读屏、地图实际跳转、剪贴板实际写入、客服实际收发。

## 四、验收矩阵

| 场景 | 期望 | 证据 |
|---|---|---|
| 门店 200 带坐标、房间 503 | 门店区就绪，房间区出错可重试；到店导航打开地图；重试只请求房间 | Node 测试「房间失败只影响房间区」 |
| 门店 503、房间 200 | 房间卡可打开；到店导航进关于页；「重新加载」只请求门店 | Node 测试「门店失败时房间照常可开」 |
| 两区都失败 | 快捷导航仍含原生客服格 | 同上 |
| 刷新时门店失败 | 到店动作回到 `unknown` | 同上 |
| 重试期间旧响应迟到 / 页面卸载 | 旧房间结果被丢弃，门店区请求不被房间重试作废；卸载后两区都不写回 | Node 测试「迟到的旧房间结果被丢弃」 |
| 只有坐标 / 只有地址 / 只有简介 | 首页与关于页给出同一动作（见 A2 表） | Node 测试「到店动作」「关于页」「首页快捷导航」 |
| 地图失败、复制失败 | 有地址弹框由客人选择，关闭零写入、确认只写一次，无地址不尝试复制；复制失败提示长按 | Node 测试「到店动作」 |
| 列表刷新后旧封面事件迟到 | 不改换到同一下标的另一间房；当前封面失败仍切紧凑卡 | Node 测试「首页封面事件按房间与封面核对」 |
| 详情轮播读屏 | 每张图带房名、图序与放大提示，预览仍用原地址 | Node 测试「详情轮播项带读屏文字」；真机读屏待核对 |
| 后端无 `/home`（404） | 首页门店区与关于页按可重试出错，不当作下架 | Node 测试（已改为分区断言） |
| 封面失效、空相册、正常图 | 前两者为紧凑布局，房名规格首屏可见；正常图可滑动、放大 | 待开发者工具与真机核对 |
