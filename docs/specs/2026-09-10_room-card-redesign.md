# 房间卡片重设计：已确认实施方案

基线：2026-09-10，源码 `1e005be`。用户要求更清楚的配色、合理的日期比例及多个客人分轨。本文件只覆盖房间卡片；未授权部署。

## 设计方向

白色卡片、深墨色文字、深靛蓝下一单、灰色历史计划。日期头从当前 64px 压缩为 44px，星期与日期横排，日期数字降到 14px；今天以日期下划线表达，不再用大数字、徽标和整列蓝底同时抢占视觉。

标题 20–23px，卡片内边距桌面 26px／手机 18px。客人事件改为紧凑摘要：姓名与绝对时间在左、倒计时重点数字在右。保留“距可入住时间”而非假定客人按时到达。有退房与入住两项时沿同一结构并列，窄屏上下排列；单项不预留另一项空白。

日历为白底、细日期分隔线，住宿条是主视觉。下一单使用深靛蓝 `#3448a5` 与白字；未来后续使用浅靛底与深色字；历史使用灰底与灰墨色字。颜色表示订单与时间关系，不代表客人实际在房或清洁已完成。只读预览可比较松石绿方向，正式默认深靛蓝。

## 多客分轨规则（替代旧方案的最少轨道规则）

- 每笔现有住宿区间独占一条显示轨道（沿用服务端已有续住合并，不在展示层按姓名合并），按计划开始、结束、订单 ID 稳定排序；不通过姓名合并客户。
- 日历头和全部轨道共用坐标轴。桌面轨道高 54px，手机轨道高 88px（上方 44px 完整姓名链接，下方 44px 住宿条），条高 44px；开始为入住日 15:00、结束为退房日 12:00，保留真实比例。
- “单独轨道”只改变展示，不表示订单冲突；真实重叠仍按原区间关系独立判定并用文字提示。
- 每个日期段默认展示最多 4 笔，超过时明确显示“展开其余 N 笔”，展开后沿原时间坐标完整列出，不限制数据读取或隐藏冲突提示。切换日期窗口时按当前窗口内订单重新计数。
- 单笔不为填空而增加空轨；可见窄片段不拉长入住区间，完整姓名和日期仍能从行程列表获取。原客户链接、完整可访问名称和已核验标记保留。
- 按用户最新要求取消横向滚动：桌面每段最多 7 天，窄屏每段最多 3 天，日期段纵向完整排列；跨段住宿按原坐标裁切并标示延续。短条主要显示姓名，完整夜数与时段通过原生行程列表补充；不能用省略号隐藏唯一客户入口。

## 保留的语义与行为

姓名、客户 ID、日期及倒计时仍来自同笔订单。计划与实际事实分开，不新增实际入住／延迟审批字段，不修改任务、凭证和订单，不增加外部请求。原有客户原生链接、CSRF、未保存防护与回跳继续有效。

“下一步”保持一行具体行动加一个按钮；准备未知的说明和来源下沉至可展开记录区，不能删掉执行敏感操作时的安全说明。无开放任务不等于任务未生成，也不直接要求重做准备。

## 文件范围

1. `src/homestay_bot/templates/admin/operations.html`：标题、客人事件摘要、行动与次级记录层级；不给真实客户创建预览弹窗。
2. `src/homestay_bot/templates/components/ui.html::room_timeline`：日期头、按订单分轨、超过四笔展开、窄条补充信息，复用客户链接。
3. `src/homestay_bot/static/app.css`：限定于房间卡片的色彩、比例、轨道和断点；不覆盖全站样式。
4. `src/homestay_bot/services/admin_operations_service.py::TimelineBar/_room_items`：仅在现有视图不足时补充独立显示轨道，不改变重叠检测、原始事件及计数。
5. `src/homestay_bot/static/admin.js`：优先原生 details；仅必要时复用已有倒计时输出分离数字和文案，不新增重复计时器。

## 验收

- 单客、双客、四客、五客以上、同名不同客户、续住及真实重叠；展开后全部可见，排序稳定，分轨不产生假冲突。
- 12／15 点端点、跨窗口裁切、长姓名和无客户 ID、计划过期但未核验退房；不得丢失来源或扩大条的时间范围。
- 桌面与 390px 手机无整页或日期模块横向溢出，条高至少 44px；键盘和无 JS 下客户链接与展开可用。
- 正文实际对比度至少 4.5:1；今天和住宿条不因相同底色混淆。日期头比住宿轨道更轻，不使用滚动数字或大幅动画。
- 原测试文件 `tests/unit/test_admin_operations_service.py`、`tests/integration/test_admin_dashboard_routes.py`、`tests/browser/test_admin_interactions.py` 按影响补最小检查；轨道策略的旧断言同步到本方案，时间几何与安全断言不得删除。
