# Lessons

## 企业微信旅游回复

- 客人可见回复不要包含网址、Markdown 链接或裸链接。
- 联网来源仍用于后台校验；客人侧只显示查询日期和最多 5 个去重来源名称。
- 验收测试必须同时断言不存在 `http://`、`https://` 和 Markdown 链接格式。

## 自然日期理解

- 武汉客服必须掌握武汉本地当天日期，并自主换算“今天、今晚、明天、明日、后天”。
- “某日入住、次日退房”和“某日住一晚”应直接换算并查询房态，不得再次要求客人提供绝对日期。
- 只有相对日期确实无法唯一推断入住或退房日期时，才向客人追问。

## 知识库缺口

- 普通问题缺少审核知识时，应由大模型给出合理回答，不因低置信度自动转人工。
- 民宿专属信息缺失时，大模型明确未确认并提供替代建议，同时提醒员工补充知识库；会话保持机器人模式。
- 交易问题无法确认时通知员工核实，但在员工真正回复前继续保持机器人模式。
- 普通问题也要审计模型主动夹带的民宿房型、设施和公共空间宣传；客人没有提问不代表模型不会自行虚构专属事实。

## 对话上下文时序

- 企业微信客人消息和机器人回复必须统一使用 UTC 时间入库。
- 模型上下文按系统实际处理顺序恢复，不得直接混排外部 UTC 时间与本地时间。
- 企业微信端到端验收必须检查回复语义是否对应最新一条客人消息，不能只检查“有回复”。

## 模型失败恢复

- 系统生成的固定失败文案及其未成功回答的问题不能再次交给模型，避免模型把故障处理当作正常答案模仿。
- 外部模型重试必须记录轮次和异常类型，但不得记录客人正文、模型原始响应或密钥。
- DeepSeek V4 Flash 同时启用 JSON 结构化输出和工具时，过长的多轮历史可能返回纯空白；上线验收应使用真实长会话重放，而不只验证单轮契约。
